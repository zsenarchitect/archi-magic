# RFC 002: Web Workspace Architecture (Issue #187)

- **Author**: archi-magic architecture team
- **Status**: Phase 0 Scoping Approved
- **Target Milestones**: Phase 0 (Scoping & Decision Record) -> Phase 1 (Local Project Page & Previews) -> Phase 2 (Team Collaboration & Comments) -> Phase 3 (Projects & Files)

## 1. Context and Problem Statement
archi-magic functions today as a conversational agent inside the Revit session and local development chat. `am-bim-viewer` renders isolated 3D model geometry in a browser tab. Teams require a unified browser workspace to view project context, inspect change previews, explore audit findings from `am-issue-board`, and review models collaboratively.

## 2. Architecture & Hosting Decision Record (Phase 0)

| Option | Architecture | Data Boundary | Operational Overhead | Decision |
|---|---|---|---|---|
| **A. Pure Cloud SaaS** | Central multi-tenant web application and database | Model data and findings upload to external servers | High compliance friction for enterprise architectural firms | **Rejected** (Breaches zero-data-leak policy) |
| **B. Local-First Sidecar (Default)** | Lightweight local HTTP / WebSocket server on `127.0.0.1` | Zero data leaves the local machine; reads directly from workspace | Zero infrastructure cost; operates offline | **Adopted for Phase 1** |
| **C. Private Office Intranet Server** | Self-hosted Node.js / Python daemon within firm LAN or VPN | All model data stays behind firm firewall on internal storage | Moderate IT coordination; role-based team access | **Adopted for Phase 2 & 3 Team Mode** |

### Data Confidentiality and Governance
- **Local Boundary Guarantee**: By default, the web workspace runs strictly on localhost (`127.0.0.1:<port>`). No geometry, parameters, or project notes leave the workstation.
- **Office Network Mode**: When enabled for team collaboration, an office HTTPS reverse proxy serves the LAN or VPN. One aiohttp service listens on loopback behind that proxy. Team members exchange individual tokens for browser sessions. Models remain on firm-managed file shares.
- **Model Change Safety**: The web workspace is strictly informational and collaborative. It cannot write directly to the active Revit database. The native Revit Keep/Discard prompt remains the single mandatory gate for model transactions.

## 4. Phased Implementation Roadmap

### Phase 1: Local Project Workspace (am-bim-viewer Extension)
- **Project Overview Page**: Display active model metadata, health score from `am-model-health`, and recent task executions.
- **Interactive Issue Board View**: Read-only rendering of `am-issue-board` findings with filtering by category, severity (`error`, `warning`, `info`), and level.
- **Change Preview Reviewer**: Render before-and-after visual parameter diffs and element highlights generated by `am-safe-change` dry-runs before final execution.
- **Integrated Model Viewer**: Link issue coordinates directly to camera viewpoints in the Three.js 3D viewer.

### Phase 2: Collaborative Annotations and Review
- **Finding Annotations**: Enable team members to add notes, verify status (`open`, `resolved`, `waived`), and assign findings to team members.
- **Sync with Issue Board**: Store finding state changes in local `.am-issues.json` format for round-trip compatibility with Git and version control.
- **Live Sync**: Broadcast audit updates to all open browser sessions via WebSockets when audits complete in the background.

### Phase 3: Project Files and Shared Recipes
- **Project Folder Context**: Connect project documentation inputs (`.xlsx` schedules, `.pdf` spec sheets, `.dwg` backgrounds).
- **Team Recipe Catalog**: Expose verified recipes from `skills/am-safe-change/scripts/recipe_library.py` with one-click dry-run execution.
- **Audit Export**: Export consolidated preflight reports and model health records to HTML and PDF formats.
