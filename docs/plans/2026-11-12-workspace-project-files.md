## Offline changes

### Project documents

Add explicit per-project document slots and consume only the local document CLI’s normalized table or comparison JSON. Accept comparison exit 1 as a valid report with differences and exit 2 as failure. Preserve the reported source filename and sheet, page or table selector, column labels, row positions and the separate mismatched, missing and actual-only collections. Keep the original documents on the source share. For a DWG background, publish an operator-supplied display name and revision and label it as a reference whose availability the browser has not verified. Use the publisher’s generation and digest checks and last-good behavior. [Document CLI](../../skills/am-markup-intake/scripts/project_document_cli.py) · [Document table contract](../../skills/am-markup-intake/scripts/document_tables.py)

Bound raw document report input at 24 MiB plus its final newline and the compact publication envelope at 25 MiB. Keep at most four configured document slots per project and 32 per service, with up to 800 MiB of last-good document files in a private spool and up to one temporary 25 MiB staging file. Reuse descriptor-relative, no-follow file reads. Cache accepted generations by opened-file identity. Do validation and document paging on one dedicated worker, off the project lock. Coalesce in-flight validations per project, then compare the validated generation under the existing lock before installing it. Return metadata from the existing review snapshot. Read pages from the validated private copy. This keeps large parsed documents out of the main project store and its four-worker pool. Admit at most one document page request service-wide and use a fail-fast 503 with retry guidance when occupied. Keep its admission token until the worker has completed and cleaned up, and the response has finished or disconnected. A disconnect during worker execution does not free admission early. Share the dedicated worker between polling and page rendering, with at most one validation batch queued and no unbounded waiting list. [Publication and project worker boundary](../../skills/am-bim-viewer/scripts/workspace_server.py)

Each document page carries its exact digest, generation and collection. A subsequent page uses all three and an index, and the server reports a revision conflict when the requested generation has been replaced. Return up to 50 records and at most 16 MiB of encoded JSON. Stop before the next complete record would exceed either limit. Validate at publish time that every individual record can fit with its provenance and pagination envelope. Test the largest legal table row and comparison key with astral text, control escapes and 128 columns, repeated pages with no omissions or duplicates, and republishing between pages. Run the existing XLSX room comparison and selected DOCX and PDF table workflows against neutral fixtures. Verify that the browser keeps the three comparison collections distinct and labels a DWG as an unverified reference.

Treat its declared tested years, inputs schema and proven counters as metadata. Show a runnable entry only when a project operator has approved its reviewed recipe bytes and the installed adapter, normalizer and verifier digests for an explicitly verified Revit year. Bind the installed sheet placement adapter to an operator-selected catalog entry by these digests. Display other entries as reference entries. The publisher stores the browser projection and private binding separately. Keep raw scripts, recipe paths, native credentials and adapter digests off browser responses. Explicitly handle both new kinds in the existing workspace snapshot, generic artifact route and review-target generation. The generic GET and HEAD return the safe summary for documents and recipes. Neither kind creates annotation targets. Only the dedicated document endpoint serves bounded pages. Test legacy routes and the dedicated endpoint with unauthorized and cross-project requests, exact Host and Origin, path replacement, duplicate publication generations, oversized records, and script and private-field sentinels.

### Audit export

Offer an authenticated, self-contained printable HTML report with the existing findings and model-health rendering functions. Capture all selected audit slot references and the project revision under the lock and render afterward. Include each slot’s generation, freshness and available producer timestamp. Record the export time separately and show unavailable audits. Bound the combined input at 8 MiB and HTML at 32 MiB. When a consolidated selection exceeds a limit, show the limit and allow a smaller selection through the same route. Keep the export response private and no-store, with all text escaped and no external assets. Verify an actual HTML download and a PDF printed from it in the browser, including severity, rule IDs, freshness and model-health totals. Build report rows from a narrow projection before calling the renderers. Preserve severity and validated rule IDs. Use installed rule descriptions where available. Exclude producer free-text fields such as message, target, source, drawing/model title, and metric hints, because CAD xref findings can put an absolute path in their message. Use the project slug for model labels and preserve model-health counts. Include only validated timestamps in provenance. Show how many findings have no installed description. Verify the report with an actual path-bearing xref audit and an injected-text sentinel. Check that no annotations, source paths or executable content appear. Give audit export its own single admitted request and one worker. Return 503 with retry guidance when occupied. Hold the token until the worker has completed and cleaned up, and the stream has completed or disconnected. Do not admit another export while disconnected work is still running. Exercise slow clients and concurrent rejected requests on both document and report endpoints while an unrelated project saves an annotation. Only the short immutable audit snapshot capture uses the ordinary review path. [Finding and health renderers](../../skills/am-bim-viewer/scripts/project_page.py)

## Native dry-run qualification and coordination

The offline document, catalog and report changes can be built and verified without a Revit host. Qualify the native contract before building or enabling the dispatcher. Use an approved saved Revit 2026 project with CPython, verified placement coordinates and the exact title block catalog. Qualify the native query and dry-run modes through the Windows Agent Runtime CLI documented in the skill. Verify the host’s active document identity, policy and target ownership before the native operation. Show the exact computed preview and require native-session user confirmation under either policy. Re-read active context and worksharing immediately before the dry run. Afterward verify the rolled-back result against a fresh query and check for borrowing separately. For an exact repeat, confirm the existing placements by fresh query and return an explicit no-op outcome. A no-op has no transaction or rollback receipt. [Placement recipe](../../skills/am-safe-change/recipes/place-sheet-views.md) · [Native safety and CLI contract](../../skills/am-safe-change/SKILL.md)

After qualification, the browser’s **Request dry run** action submits the approved recipe identifier, a separate operation ID, and inputs accepted by the installed placement normalizer. Keep the validated placements, sheets and clearance object intact for the native adapter. Its validator returns flattened tuples for analysis. Require an editor, exact Origin and the existing body limit. Reject caller-provided command, path, script, plan, apply receipt, runtime mode, script mode and Revit-year overrides. The local adapter fixes the Runtime mode to dry run and script mode to dry-run. Only a separately configured operator principal may claim a request for its own project. The web service never executes a native script. A claim starts the operator workflow. The preview confirmation still takes place in the native session.

Persist request and receipt records in a separate 2 MiB project file under the existing exclusive project lock. Allow up to four unresolved and 100 total records. Deduplicate within a project and actor by operation ID and normalized request digest. Claim and finish transitions compare the current state and claim ID before writing atomically. A later result cannot complete an interrupted or different claim. Store concise verified outcomes and keep native logs with the operator. Show only a requesting editor’s records and let the designated operator see its project queue. Preserve terminal records and idempotency until a maintenance archive. Rotate the queue namespace on archive so operation IDs issued in a retired namespace are refused. Saturation returns an explicit error while normal annotations remain available. No automatic retry after a claim. Prove restart, competing claimers, stale baseline, altered adapter, wrong host, borrowing, forged results, saturation and native cancellation. The end-to-end test starts in the browser and ends with a verified native rollback and fresh model query.

## Release and rollback

- Remove the document slots or disable the report route and links to roll back their respective features. Verify direct report GET and HEAD after disabling it. Disable new native requests and claims before dispatcher rollback, then finish or reconcile every in-flight run using the native receipt and borrowing readback. Keep interrupted requests, receipts and review state across restart.
- The native test needs an approved Revit session, representative model, operator and policy. The office rollout needs the approved LAN or VPN origin, proxy, roster and physical project roots. The existing request for host access remains the open dependency. Local verification can use disposable roots and the existing TLS proxy fixture.
- Close [#187](https://github.com/zsenarchitect/archi-magic/issues/187) after Phase 1 shows a real Revit audit and preview, the exact-head GitHub CI jobs pass, a fresh reviewer verifies the release through the approved office HTTPS host, and Phase 3 demonstrates actual document provenance, HTML/PDF export and the browser-to-native verified dry run.
