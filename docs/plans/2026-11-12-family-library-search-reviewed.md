# Search the Revit family library and place a reviewed type (#153)

[Issue #153](https://github.com/zsenarchitect/archi-magic/issues/153) requests a library index, search by name, category, and parameter, paths and thumbnails in results, and reviewed loading and placement that reuses an existing project type. Baseline `0c523067c4313bd9e8c3898be4ffd32d874463d7`. The [manufacturer import skill](../../skills/am-import-from-manufacturer-rvt/SKILL.md) copies system types from open RVT models. This workflow targets loadable RFA files and uses the [safe-change workflow](../../skills/am-safe-change/SKILL.md) for project edits.

## Discover and stage the library

1. Accept one explicit local root or a user-selected, locally available Autodesk Docs root. Qualify Connector paths on the installed Windows build using hydrated and dehydrated fixtures with reads instrumented to detect automatic hydration. Permit direct discovery only when the file is proved resident without reading it and the path passes the ordinary-file and ancestor checks. Reject cloud placeholders, unrecognized attributes, and reparse paths. If a hydrated Docs path still uses a reparse tag, have the operator export the selected files and their companion catalogs to an approved ordinary local folder. Index that export with its root label and exact relative paths. Keep the generic reparse guard intact. [Autodesk Docs file availability](https://help.autodesk.com/cloudhelp/ENU/CONNECT-User-Guide/files/Files_Folders_Docs.htm)
2. Walk only the selected root using relative path components and ordinary directories. Reject traversal, aliases, symlinks, reparse points, alternate streams, hardlinked leaves, and case-colliding names. Record root and ancestor identities during traversal. Use pinned parent handles and a no-follow leaf open, or a platform equivalent that demonstrably prevents an ancestor or leaf swap from redirecting the read. On POSIX, walk through directory descriptors. On Windows, qualify no-follow handles that reject reparse points and prevent replacement while held. Recheck path ancestry and root containment against the recorded identities before and after copying. Compare the leaf's descriptor identity, size, modification time, and link count with the enumerated and final path states. Apply the same checks to companion catalogs. Reject changes before publishing or passing staged bytes to Revit. The existing path and stable-copy checks are precedent, with recursive containment to be implemented and tested here. `skills/am-model-health/scripts/cad_file_inventory.py:24–39`, `skills/am-model-health/scripts/batch_model_audit.py:25–68`.
3. Start with caps of 10,000 directory entries, 12 levels of depth, 500 RFAs, 256 MiB per RFA, 4 MiB per catalog, 4 GiB of staging, and 1 GiB of free headroom after staging. Stop discovery after 120 seconds. Record skipped paths, coverage, and the limit that stopped work. Use a new private workspace outside the library, one protected content-addressed subdirectory per source pair, and exclusive file creation. Preserve original RFA and catalog basenames so Revit can resolve the companion. Pin root-relative path, exact RFA basename and SHA-256, and companion catalog presence or absence, exact basename, and SHA-256. Reject ambiguous catalog names. Check both files and the absence case before and after staging, before and after native reads, and immediately before a native load. An added, removed, or changed catalog invalidates the selection even when the RFA is byte-identical. Follow the existing batch size and free-space checks. `skills/am-model-health/scripts/batch_model_audit.py:93–127`.

## Enrich, refresh, and search

4. Use an isolated disposable Revit worker for every native family open, including metadata reads. Start with a known open-document baseline and no production model. Open only the exact pinned staged source, verify the opened path and family document identity, and process one source pair at a time. Read the family/category identity, embedded types, and selected typed values with FamilyManager. Record each receipt against the discovery manifest, exact source pair, extraction schema, and actual Revit build. Check the result of `Close(false)`, verify the open-document baseline, and rehash the staged pair. Stop the worker on an unexpected document, failed close, or changed staged input. Reuse the batch reader's lifecycle checks. Its project-audit entry point rejects family documents. Qualify paired type-catalog reading against a native fixture before treating catalog types as selectable. Report incomplete catalog coverage explicitly. `skills/am-model-health/scripts/read_batch_models.py:98–137,151–158`. [Autodesk FamilyManager](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/1cc4fe6c-0e9f-7439-0021-32d2e06f4c33.htm) · [Autodesk FamilyType](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/7f15b213-c99b-db59-3622-3280757b82d9.htm)

Bind the image hash to the paired source identity, exact family/category/type, extraction schema, Revit build, and refresh receipt. An absent image keeps the type searchable with a visible reason. Check the family-thumbnail workflow if it lands before adding another rendering path. Limit enrichment to 250 types and 50 requested parameters per source, 5,000 indexed type rows, 128 MiB of thumbnails per refresh, 60 seconds per source, 20 minutes per worker batch, and 32 MiB of index output. Preserve a partial result with explicit coverage when a cap prevents completion. 6. Publish a versioned, bounded local index. Allocate a monotonic refresh generation under a per-index process lock and bind it to the root identity, bounded discovery manifest, source pairs, schema, and worker build. Reuse unchanged enrichment only when all source and extraction identities match, and bind the reused receipt to the current manifest. Reject mixed-generation results, changed inputs, and incomplete receipts. Recheck discovery and source identities before publication. Under the same lock, confirm the generation still owns publication and atomically replace the index from a same-directory temporary file. In a partial scan retain unconfirmed, unreadable, dehydrated, or changed rows only as visibly unavailable and ineligible for placement. 7. Search the published index without Revit. Normalize names and category filters. Match parameters by stable ID where available. Keep original typed values, units, and display text. Report ambiguous parameter names and incomplete coverage. Return family, exact type, category, root-relative path, and an image reference with verified identity or its unavailability. Keep equal names from different paths distinct. No discovery, refresh, or thumbnail action edits the original library.

## Acceptance and open dependencies

Prove exact local search results with duplicate filenames and names across folders, multiple types, typed text and numeric parameters, distinct source thumbnails, a missing thumbnail, and catalog-only changes. Exercise ancestor swaps and aliases, unhydrated and qualified hydrated Docs files or a reviewed ordinary export, source removal and mutation during enrichment, incomplete discovery, competing refreshes and an interrupted publication. Verify the selected record's current pair and exact path at the handoff. Run native positive controls for active and inactive existing-symbol reuse without a reload, absent-type load, a sibling-preserving missing-type load, and absolute XYZ and rotation on a nonzero level. Exercise ordinary and shared family collisions, an unapproved dependency or overwrite, incomplete effect evidence, Discard, and a forced late failure. Prove unchanged originals and pre-existing model state, kept instance identity and pose, and complete restoration after rollback. Record the exact branch revision, Revit and Connector versions, fixture scope, and run receipts.

The approved Windows Revit host, disposable project, and authorized Docs fixture are external dependencies. Measure Windows handle and hydration behavior, native catalog and image coverage, bridge callbacks, placement coordinates, and visibility of exact effects before Keep. Keep unqualified paths and placement modes blocked with a specific reason. Direct cloud API indexing, new credentials, system types, editing source files, and automatic replacement of project family definitions remain outside the initial workflow.

## Second-review implementation notes

- Run at most one staging and enrichment worker per index. Reserve space against the combined staging, scratch and retained thumbnail budget. Keep assets referenced by the published index through interrupted refreshes and remove superseded assets only after successful publication. Enforce timeouts from outside the native worker. An unreadable or changed row stays unavailable even when directory enumeration succeeds.
- Show load, reuse, activation and dependencies in fields the renderer displays. Compare stable pre-existing IDs and fingerprints across attempts. Record new IDs independently for each run and compare the approved semantic identities.
- Compare the dry-run effects with the approved preview and show the result before the real attempt. Reject a mismatched dry-run record. Verify the expected ask-policy approval in the saved bridge result. Include a nonzero offset and rotation in the native pose fixture, and qualify worksharing checkout separately from model restoration if workshared hosts enter scope.

## Local discovery entry point

Run `python skills/am-model-health/scripts/family_library_discovery.py /absolute/library/root > discovery.json` on a host with descriptor-relative, no-follow directory access. The manifest lists exact relative paths, directory identities, and RFA and companion catalog hashes. Exit 0 means the scan finished without skips. Exit 1 means the manifest records partial coverage. Exit 2 means the root or platform could not be used. The Windows path opens ordinary local directories with no delete sharing. It rejects cloud, offline, recall, and unrecognized attributes and reads source files without sharing write or delete access. Native Windows handle tests, Autodesk Docs intake, private staging, and Revit enrichment remain pending. [Microsoft CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) · [Microsoft file attributes](https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants)

## Private staging entry point

Run `python skills/am-model-health/scripts/stage_family_library.py discovery.json /absolute/private/staging-parent --path Fixtures/Example.rfa > staging.json` from the repository root. Repeat `--path` for additional reviewed families. Use Python 3.13 or newer on Windows for private directory creation. Staging checks the discovery digest, source ancestry, companion catalog state, free space, and the hashes of the new copies. A failed stage emits no receipt and reports the unpublished workspace if one was created. Native enrichment must verify the staging receipt and files again before opening them.
