# Share project review on the office network

[Issue #187](https://github.com/zsenarchitect/archi-magic/issues/187) calls for comments on findings and previews, assignment, status and live audit updates. [RFC 002](../rfcs/002-web-workspace.md) selects the office LAN or VPN for team mode and local operation for individual review. Filed gap confirmed at `b28ac21c53720f7d90bb1c87fa83cbb2521150d0`. The local renderer accepts saved artifacts and blocks connections with its content policy. The board parser has fixed issue numbers and can return duplicate numbers as a warning. Neither implements browser collaboration. [Project page](../../skills/am-bim-viewer/scripts/project_page.py) · [Issue board parser](../../skills/am-issue-board/scripts/issue_board.py)

## Office boundary and synchronization

4. Use `aiohttp` 3.14.5 and Python 3.10 or later for one HTTP and WebSocket process. Its installed server accepts `client_max_size`, `max_msg_size`, heartbeat, writer limit and Secure/HttpOnly/SameSite cookie options. Bind only to loopback behind an office HTTPS proxy. Validate the canonical TLS authority at the proxy and application. Preserve the approved Host upstream, ignore client forwarded headers, forward WebSocket Upgrade and Connection, and disable proxy caching. Require exact Origin for login, mutation and WebSocket upgrade. HTTPS login exchanges a per-user token for an expiring opaque session stored server-side. Credentials are operator-provided hashes outside served paths. Cookies are Secure, HttpOnly and SameSite=Strict. Check membership on every GET, HEAD, mutation and subscription, and again before sending WebSocket notifications. Close sockets on logout, expiry or revocation. A viewer can read or subscribe. An editor can annotate and assign a project member. Suppress project content, paths, token and cookie values from logs. Apply private no-store headers to protected responses. Test cross-project, unauthenticated and wrong-origin requests after a valid client has warmed the proxy. [aiohttp server reference](https://docs.aiohttp.org/en/stable/web_reference.html) · [Nginx proxy headers](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_set_header) · [Nginx WebSocket guidance](https://nginx.org/en/docs/http/websocket.html)
5. Keep HTTP bodies below 32 KiB at the proxy and app, comments below 4 KiB UTF-8, audit/preview/board data below 4 MiB each, sidecars below 16 MiB and viewer input JSON and generated viewer responses below 256 MiB each. The local capacity probe generated 5,000 elements and 1,500,000 triangles. Its input measured 164,565,566 bytes and the actual offline builder produced 166,245,738 bytes. This rules out the original 128 MiB ceiling. Qualify the 256 MiB boundary and concurrent serving through the actual proxy before release. Send viewer bytes through authenticated HTTP. WebSocket messages carry only revision and freshness changes. Disable WebSocket compression, allow at most 1 KiB inbound and outbound payloads, use one reader, a 20-second heartbeat, a 75-second proxy read timeout and a two-second write deadline. Keep at most one pending revision per connection and close slow clients. A reconnect refetches current authorized state. Start with 50 connections total and 10 per project. Bound login attempts, 200 active sessions and at most four concurrent artifact workers. Apply proxy connection and request limits as well. [Exporter limits](../../skills/am-bim-viewer/scripts/export_bim_json.py) · [aiohttp WebSocket usage](https://docs.aiohttp.org/en/stable/web_advanced.html)
6. Use one watcher per project with connected reviewers. Poll the configured slots at two-second intervals, read and validate completed artifacts off the event loop, and build viewer bytes off the event loop. Use a documented local publisher command for saved audit, preview and board results. Use the existing run-record validators and one configured publisher per slot. Publish via atomic rename with a monotonic generation in the same JSON envelope. Persist the last accepted generation and digest. Under the same project lock used for edits, compare generation, install the active catalog and commit the audit revision before announcing it. Reject older generations and conflicting reuse, including validations that complete out of order. A malformed or incomplete slot keeps its last valid in-memory view and sends a stale notification. After restart, show the slot as unavailable if no valid bytes match or supersede the persisted generation. Do not render a lower generation or accept new edits against an unavailable catalog. Retain existing annotations in history. Notify recovery when valid data returns, even when its digest matches the last good digest. Test malformed slots before and after restart, reverse-order completion, publication concurrent with annotation, simultaneous projects, and oversized inputs.
