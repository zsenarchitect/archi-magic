[Issue #163](https://github.com/zsenarchitect/archi-magic/issues/163) asks to transfer selected family parameters, including formulas and per-type values, to other project families without breaking existing references. The marketplace ledger records a family definition copier (`docs/plans/2026-11-05-marketplace-ledger.md:91`). The implementation starts from local revision `0b9b77ae764edc216a69cf0bbc9780944c42053e`, with #153 and #165 primitives awaiting publication and native qualification.

2. Bind an explicit target type map for each family. Match by exact name only when unique; otherwise require a reviewed mapping. A selected target definition can be reused when identity and full spec match and reviewed values/formula already agree. A mismatched existing definition or value is a blocked conflict. Support ordinary family definitions and exact compatible existing shared definitions first; add a shared definition only with a qualified matching ExternalDefinition. Do not change a user's shared-parameter file. ## Limits and acceptance

- Initial native scope is a saved standalone disposable Revit 2026 project, local protected sources, and writable private target families. Cap at 20 targets, 50 chosen parameters, 250 types per family, 4 MiB of family state, and 4 GiB of staged and derived bytes. Keep one supervised native worker and at least 1 GiB free. Stop on partial reads, collisions, unsupported values or effects. Confirm host exit before cleanup. Use the protected library and family inventory limits at `skills/am-model-health/scripts/read_batch_family_derivation.py:13,28` and `skills/am-model-health/scripts/prepare_batch_family_derivation.py:119`.
- Positive control transfers one arithmetic formula with existing and new dependencies and two mapped target types. Compare exact formula and evaluated values after reopen and after project Keep. A repeated transfer performs no writes when every requested definition, value, and formula already matches. Prove the target's pre-existing formulas still evaluate correctly. Negative controls include missing dependency, case mismatch, cycle, spec conflict, stale file, incompatible shared definition, unexpected nested change, and a late failure that restores the exact baseline. Test Discard and Keep separately.
- Rollout is offline dependency and plan checks, active-family native dry run, verified private export, project dry run, and separately approved Keep. External dependencies are the authorized Windows Revit test host and the pinned pyRevit bridge. Open questions are exact formula grammar coverage, effective callback and family reload behavior, preservation of shared/nested state, and measurable native effect IDs. Workshared projects, automatic destructive reload, and unsupported category reference resolution remain outside the first qualified path.
