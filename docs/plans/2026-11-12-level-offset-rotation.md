# Match rotation, offset, and reference level in Revit (#168)

[Issue #168](https://github.com/zsenarchitect/archi-magic/issues/168) requests three operations. Match a reference element's rotation or offset, or assign the closest eligible level while preserving absolute elevation. Start from main at 0c523067c4313bd9e8c3898be4ffd32d874463d7. The [transform recipe](../../skills/am-safe-change/recipes/element-transforms.md) already routes moves and rotations through a preview, native dry run, and readback. Read relative operations from actual model state before generating a request. Changing the level needs a separate approved parameter edit and preservation check.

## Supported inputs and assumptions

- Use a reviewed host project and explicit element IDs. Start with project instances whose supported native properties can be read and written without recreating the instance. Read the element and type UIDs, location, level, host, group, pin, and editability before deciding eligibility. Show blocked rows with the failing property. Leave hosted, grouped, linked, pinned, two-level, work-plane-based, and curve-driven cases pending explicit native qualification.
- [LocationPoint.Rotation](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/43aea45e-dd1c-6a35-2fd5-1f99356708df.htm) reads insertion rotation in radians. Match point-based model elements around their own vertical axes using the shortest signed angular delta. Review a deterministic half-turn convention. Preserve each pivot and report the before and after rotation. A reference is read-only.
- Read a consistent offset definition for every selected and reference element. For the initial one-level fixture, use a level-relative length offset and require an empirical relationship between location Z, the level, and that offset. [FamilyPlacementType](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/2abb8627-1da3-4069-05c9-19e4be5e02ad.htm) distinguishes one-level placement from hosted and two-level placement. Do not assume a built-in parameter is present or writable because the family placement type matches. Qualify the exact Revit parameter identifiers, storage types, and offset sign on a disposable fixture. Match the reference's level-relative offset and disclose the proposed change in absolute height.
- Compare eligible levels using [Level.ProjectElevation](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/895ef506-bfea-cc4e-31f8-aad2af6672e4.htm). Before enabling writes, verify the relation between this project-relative coordinate and the actual insertion Z for a fixture with a nonzero project-base elevation and a shared-origin display setting. If the coordinate frames differ, convert explicitly using verified Revit data. Block ties and incomplete level inventories. The proposed new offset is absolute insertion elevation minus the new level elevation in the same frame. Preserve a no-op when the closest level is already assigned.

## Execution and evidence

1. Read the actual model and calculate the three preview variants. Bind approved rows to the exact project, reference, target identities, parameter metadata, level inventory, and reviewed values. Reuse the existing transform shape for verified rotations when it can preserve those bindings. Keep reference and no-op rows outside the write set. This stage can be stopped without model changes.
2. In a disposable project, verify the supported category and parameter pairs. Try the level assignment and compensating offset in one rolled-back transaction. Check actual level, location XYZ, orientation, and element UID after regeneration. Reject hidden side effects, failed constraints, or a changed offset contract. For offset matching, confirm the resulting relative offset and that only the intended vertical movement occurred. Repeat the original read after rollback.
3. Wire the qualified rows through the existing am-safe-change ownership and preview workflow. Reread the same reference, targets, and levels before dry run and before Keep/Discard. Apply a reviewed batch atomically. Roll back on any discrepancy or unexpected changed element. Do not change a type, host, or group to make a row writable.
4. Prove the outcome on a saved disposable Revit model. Read independent XYZ and level before and after, with proposed initial tolerances of 0.001 ft in position and 0.00001 rad in orientation. Include negative offsets, changed references, exact ties, duplicate level elevations, unsupported elements, and Discard. Measure against the recorded XYZ rather than the offset field alone. Record the tested commit, Revit build, qualified parameter IDs, receipt, and independent readback. If a kept fixture changes elevation, restore from the fixture baseline and leave the issue open.

The authorized Windows Revit host and a representative one-level family fixture are external dependencies. The unresolved questions are which category and parameter combinations Revit lets us update in place and how dependent geometry behaves. A pure preview and API doubles can establish arithmetic and stop conditions. Native readback is required for the issue's preservation criterion. Rehosting, level creation, moving linked elements, and silently substituting a different level are outside this issue.
