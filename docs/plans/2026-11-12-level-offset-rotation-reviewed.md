# Match rotation, offset, and reference level in Revit (#168)

[Issue #168](https://github.com/zsenarchitect/archi-magic/issues/168) requests three operations. Match a reference element's rotation or level-relative offset, or assign the closest eligible level while preserving absolute elevation. The implementation baseline is main at `0c523067c4313bd9e8c3898be4ffd32d874463d7`. Use the existing [safe-change workflow](../../skills/am-safe-change/SKILL.md#the-8-steps-do-all-of-them-in-this-order) for context, approval, dry run, and verification.

## Supported inputs and calculations

- Use a saved host project and explicit element IDs. Positively establish that the document is a project, each input belongs to that document, and each instance is in model scope. Require a finite `LocationPoint` XYZ and rotation. Read element, type, level, host, and group identities, plus pin and editability state. Missing or unreadable scope or geometry blocks the row. An explicitly qualified one-level point-based family is the first native fixture. Hosted, grouped, linked, pinned, two-level, work-plane-based, and curve-driven cases require separate qualification. Show the reason for each blocked row. Read a reference only for matching operations and exclude it from every write set.
- [LocationPoint.Rotation](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/43aea45e-dd1c-6a35-2fd5-1f99356708df.htm) reports insertion rotation in radians. For target angle `a` and reference angle `r`, use `((r - a + π) mod 2π) - π`, with an exact half-turn resolved as `-π`. Rotate about the target's own insertion point and the model Z axis. Compare final angles by circular difference. Keep the native plan in radians. Convert explicitly if using the degree-based pure transform math to render the preview. A rotation match preserves insertion XYZ.
- [FamilyPlacementType](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/2abb8627-1da3-4069-05c9-19e4be5e02ad.htm) distinguishes one-level placement from hosted and two-level placement. Before enabling an offset or level write for a category and placement type, empirically qualify the native level and offset parameter pair. Record exact parameter identifiers, instance binding, storage types, length spec for the offset, read and write availability for each operation, and the units and sign convention. Verify that the level parameter agrees with the instance's native level identity. Match only comparable level-relative offset contracts and show the predicted absolute height change. Preserve target XY, rotation, and level during offset matching.
- Convert [Level.ProjectElevation](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/895ef506-bfea-cc4e-31f8-aad2af6672e4.htm) and insertion Z to a verified common coordinate frame. Verify the conversion with independent native fixture measurements, including a nonzero project-base elevation and a shared-origin display setting. Confirm that the qualified contract satisfies `insertion_z ≈ level_z + offset` in internal feet, including a negative offset. Do not derive the conversion from the one relationship it is meant to check. Block incomplete candidate inventories and unverified conversions. Rank eligible levels by `abs(insertion_z - level_z)`. If another candidate's distance is within 0.001 ft of the minimum, block as ambiguous before considering a no-op. If the unique nearest level is already assigned, show unchanged. Otherwise the compensating offset is `original_insertion_z - new_level_z` in the verified common frame. Check the new level UID and preserve the same instance's XYZ and rotation.

## Acceptance and boundaries

- Pure tests cover wraparound in both directions, half-turn sign, no-op, negative offsets, exact and near ties under a shifted frame, duplicate level elevations, and incomplete inventory. Guard tests exercise unknown rotation, stale reference or target UIDs, changed parameter metadata, a missing or extra telemetry ID, another-document effect, an offset binding change after releveling, and a late failure after multiple targets have changed. Assert complete rollback, including the reference and each target's baseline.
- In a saved disposable Revit model, run positive controls for rotation and relative-offset matching. Verify a kept relevel changes the level to a different UID and changes the compensating offset, on the same element UID, with XYZ preserved within 0.001 ft and rotation preserved within 0.00001 rad. Measure from independent before and after model queries. Run separate Discard and late-failure trials that prove restoration. Record the exact native parameter contract, coordinate-frame checks, approval receipts, and measured results before closing #168.

The authorized Windows Revit host and representative one-level family fixture are external dependencies. Category-specific writability, coordinate conversion, and visibility of native effects while rollback is available are unresolved until exercised. Rehosting, level creation, and moving linked elements are outside this issue.
