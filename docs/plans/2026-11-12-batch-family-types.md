# Batch family types from a table

GitHub [#165](https://github.com/zsenarchitect/archi-magic/issues/165) asks to batch-load RFA families, create types from tabular sizes, and report existing types without duplicating them. The marketplace ledger lists the request under safe change (`docs/plans/2026-11-05-marketplace-ledger.md:93`). Base `3154e6907606392f7c71d2f4b4a53d4955692884` contains the local #153 staging and verification primitives. Their publication and native Windows qualification remain pending. The first offline phase can run with fixtures. Native phases require the compatible #153 primitives and measured Revit and pyRevit builds.

## Read and classify

1. Import UTF-8 CSV with a fixed comma delimiter, exact library-relative source RFA, exact embedded seed, exact requested type, and explicit parameter and unit headers such as `Width[mm]`. Use the standard CSV parser, including escaped quotes and CRLF. Reject duplicate headers and row keys, missing values, nonfinite decimals, and invalid or ambiguous identities. Cap input at 1 MiB, 50 source families, 250 rows, and 50 size columns. Bind the exact table and normalized rows to the discovery manifest, each source's ancestry and bytes, and catalog presence or absence. Reuse the protected discovery and staging at `skills/am-model-health/scripts/stage_family_library.py:119,159`.
2. Read the saved standalone target and each protected family copy. Bind exact source family and category, seed identity, requested size parameter definitions, project family/type IDs, and the Revit build. Report existing exact project types and value differences without editing those types. Block case or identity ambiguity and distinct source paths converging on a project key. Treat a collision in either the reviewed project or an embedded source family as unavailable for creation until classified explicitly. Never substitute a catalog-only or catalog-shadowed seed for the reviewed embedded seed. Review the full selection or explicitly approve an eligible subset with a new digest. An all-skip batch performs no derivation or project write. Reuse the paired source checks and project inventory at `skills/am-model-health/scripts/read_family_library.py:38,193` and `skills/am-model-health/scripts/read_family_placement.py:17,115`.
3. Use a writer-specific family query for `IsInstance`, `IsReadOnly`, `IsDeterminedByFormula`, reporting flags, storage type, exact parameter name, and data type. Prefer shared GUID or exact source-bound ID. Use names only if the family read resolves one definition with the expected spec. Initial editable scope is writable, non-formula, non-reporting type Double parameters. Map `mm`, `cm`, `m`, `in`, and `ft` to Revit unit IDs for length. Use `1` for a dimensionless Double with the Number spec. Reject Integer, Yes/No, invalid unit/spec pairs, nonfinite results, and unsupported dimensions. Convert lengths with `UnitUtils.IsValidUnit` and `ConvertToInternalUnits`. Keep both original decimal text and the verified native value. ## Acceptance and release boundary

- Positive control: two exact types from each of two source families, two distinct seeds, real nonzero sizes, and exact new IDs. Keep, read back, rerun the same table, and prove all rows skip with zero writes. A separate existing-type fixture reports differing values without editing or duplicating it.
- Denial controls: duplicate row, invalid unit/spec, ambiguous or catalog-only seed, source or derived hash drift, an ordinary/shared conflict, unexpected dependency, and a forced mid-batch failure. Check zero project writes where blocked before mutation, and exact independent restoration after rollback. Test native Discard separately from forced failure.
- Rollout order is offline read and review, native derivation qualification, derived receipt verification, project dry run, then separately approved native Keep. Stop before advancing when native evidence is missing. The Windows fixture, supported Revit bridge and #153 worker lifecycle are external dependencies. Workshared and production models, remote libraries, formula edits, new shared parameters, and automatic replacements remain out of scope for the first qualification.
