# Batch family types from a table

GitHub [#165](https://github.com/zsenarchitect/archi-magic/issues/165) asks to batch-load RFA families, create types from tabular sizes, and report existing types without duplicating them. The marketplace ledger records the request under safe change (`docs/plans/2026-11-05-marketplace-ledger.md:93`). This work is based on `3154e6907606392f7c71d2f4b4a53d4955692884`, the local family library branch for #153. Publication and native Windows qualification of that dependency are still pending.

## Plan

Bind each table to the reviewed discovery manifest, exact source ancestry, and paired catalog presence or absence. Preserve exact path, type names, and column values. Reject duplicate row keys and ambiguous parameter identities. Cap input at 1 MiB, 50 families and 250 rows per batch. Report blank, ambiguous, and ineligible rows. Verify delimiter, escaped values, invalid units, duplicate rows, and Unicode fixtures before any Revit calls. Reuse discovery and staging at `skills/am-model-health/scripts/stage_family_library.py:119,159`.

Identify exact project family/category/type and distinguish existing, new, source missing, collision, and unsupported. Existing exact project types are skipped and reported even if the table's desired values differ. Report those differences without updating values. Keep same-named inputs from distinct paths separate and block when they converge on one project key. Confirm complete reads, standalone project identity, and actual Revit version and build. ## Acceptance, rollback, and scope

- Verify one batch with two source families, two types per source, at least one existing type with differing values, one duplicate table row, a changed source, a wrong unit, and a shared-family conflict. Show correct internal-unit values on the kept exact types and no additional type on rerun. Test forced mid-batch failure, Discard, and user Keep separately.
- Before any model write, confirm native worker and bridge capabilities on the authorized Windows Revit fixture. Confirm protected reads, no-overwrite callback behavior, correct group rollback, and decision-record readback. Keep all edits on derived copies until the reviewed project transaction. Stop on an unresolved worker and preserve receipts. Discard or failed validation rolls back the project group. A successful Keep is one undo entry. Rollout starts with offline validation and previews, then native scratch generation, then disposable project dry run, then explicitly approved native Keep.
- Open questions include which unit symbols to accept, the native exact-name collision behavior, how to prove source-derived parameter equality, and which sibling-load cases the API can preserve. Answer these with Revit's API and exact native fixtures. Workshared projects, production models, formula editing, shared parameter creation, remote library changes, and implicit parameter or seed selection are outside the first qualified path.
