# Reviewed plan dimensions for grids, walls, and openings (#146)

[Issue #146](https://github.com/zsenarchitect/archi-magic/issues/146) requests overall and grid dimension strings in plan views, opening dimensions on chosen walls, and a report of unresolved references. The pinned baseline is `0c523067c4313bd9e8c3898be4ffd32d874463d7`. Use the [safe-change workflow](../../skills/am-safe-change/SKILL.md) for context, ownership, approval, and readback. The [Revit API notes](../../skills/am-revit-api-docs/SKILL.md) identify the native dimension type overload.

## Read and compute the preview

1. Before reading, call `get_context` and `get_skill("revit-scripting")`. Bind the saved host project UID and path digest, Revit version and build, engine, ask policy, active floor plan ID and UID, and the reviewed linear dimension type ID and UID. Read the native view plane and crop, selected source identities, and complete existing dimension inventory for the destination view. Reject templates, perspective and unqualified dependent views, links, stale identity, and incomplete visibility or inventory. Bound the query and result to 20 requested strings, 64 references per string, 2,000 existing dimensions and 2 MiB serialized data. If a bound is reached before the inventory is complete, block the affected preview instead of relying on a partial search.
2. Validate a finite native origin and an orthonormal right, up and normal basis. Normalize near-unit basis vectors, confirm orthogonality and handedness against the native normal, and reject a degenerate or inconsistent frame. Validate finite distinct placement endpoints in that plane, with perpendicular distance no greater than 0.001 ft, and a line longer than both the station tolerance and Revit's short-curve tolerance. Only then project the endpoints into the verified plane and use the normalized line as the dimension axis. For every witness, establish the corresponding straight direction or planar face trace in this view. Require its normalized direction to be perpendicular to the axis within 0.00001 rad. Reject skew, missing geometry, degenerate traces, and ambiguous intersections. Derive each signed station by projecting the intersection point minus the normalized placement origin onto the axis. Sort by increasing station. Require adjacent stations more than 0.001 ft apart and compute segment lengths from successive station differences. Keep full precision for checking and round only for display.
3. For grids, record the extent mode of each end of each selected datum. Use the matching model or view-specific straight extent and require the placement line to cross the supported visible span. Block unresolved or mixed extent modes until the native fixture qualifies their reconstruction. Keep the native datum reference strategy distinct from the extent curve. Bind its stable identity and owner, and qualify that exact reference form against the destination plan. Use one string per set of straight parallel host grids. [Autodesk datum extents](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/2f93dd88-baac-8e61-377e-b937f3faaff6.htm)
4. For overall dimensions, resolve native planar references for the reviewed interior or exterior side of two straight parallel host walls. Verify ownership, the opposing planes, and their traces in the view plane. Read the trace crossings and verify the selected face has usable geometry in the reviewed view. A location line or bounding box cannot supply a side reference. For multiple plausible faces, require exact reviewed reference selection. Block unresolved stepped, split or stacked cases and show their source and reason. [Autodesk wall side references](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/589b9363-c2cc-52d9-6ba1-fc8e8f912b27.htm)
5. For openings, inventory the door and window instances hosted on the chosen walls. Bind wall, instance and symbol IDs and UIDs, transform including reflection, flip state, and exact left and right stable references and owners. Establish their physical witness geometry and stations independently through exact resolvable planes or through measurements of the same family reference planes with the reviewed symbol geometry and instance transform. Pin the measured offsets and their provenance to those identities and states. A nominal type width may be displayed separately. The provisional dimension value cannot establish its own expected measurement. For a mirrored instance, sort the physically measured stations and carry the corresponding references with them. Block an opening if the actual planes, their positions, or their correspondence to the stable references remain ambiguous or are hidden or unsupported. [Autodesk family instance references](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/a8a7dc74-db8e-a7b6-a9c8-869397cca6b4.htm)
6. Canonicalize the reference chain, every adjacent reference pair with its segment value, and the normalized line together. If orientation is reversed, reverse references, pair order and the corresponding values together. Compare canonical signatures across the entire proposed batch and against the complete existing-view inventory. Use the matching type and geometric tolerances for the line direction (0.00001 rad), perpendicular offset and projected endpoint extent (0.001 ft), independent of endpoint order. Do not use rounded keys to decide equality. Existing matches are no-ops. Coalesce repeated requests only if they have the same reviewed signature and preserve their diagnostics. Block conflicting proposed or existing strings that cannot be classified. [Autodesk stable reference representation](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/9d821d63-5b4a-b814-25b2-b92f7d5d1425.htm)
7. Render a `kind: change-preview` document with the existing `skills/am-schedule-view/scripts/render-table.ps1`. Set `review_only: true`, use a stable `keyColumn`, before and after rows and warning keys matching blocked rows, and omit executable steps. Distinguish proposed, blocked and already-existing rows. Keep executable data in a separate recipe-specific, versioned writer payload. Bind each payload to the preview, view, line, ordered stable references and source identities, expected segment pairs and values, and native type. A blocked row cannot enter any payload. A separate reviewed preview may select resolved rows, with the blocked diagnostics retained in the original report.

## Qualify references and effects before persistence

8. A complete experimental candidate has resolvable references, independent expected stations, and all geometry and identity evidence, while native acceptance of that specific reference strategy is pending. Mark it explicitly as an experimental row. Generate a distinct versioned rollback-only qualification payload that only the fixture probe accepts. This payload cannot enter the persistent writer. The probe may test this complete candidate without prior native qualification. Missing references, ambiguous geometry and ungrounded measurements remain blocked. Use a saved disposable project with ask policy, check and bind the destination view's ownership, show the exact preview and obtain approval for the exact experimental payload. The destination view is the only existing ownership target. Grids, walls, opening instances and the dimension type are read-only sources and stay out of `ownership_ids`. Recheck context, engine, build, policy and ownership before each mutation and stop on any mismatch.
9. Run the qualification under `dry_run: true`. Immediately reread the entire bound basis and compare it to the reviewed payload, including the existing dimension inventory. Reparse the stable references and verify the same document, owner, kind, geometry and station before constructing the native `ReferenceArray`. Open a transaction group that remains reversible through an inner transaction's provisional commit and the effect audit. Use one inner transaction for the batch and pass the reviewed dimension type element to the correct `NewDimension` overload. Regenerate and read the new dimensions before inner commit. Any failed reference, line or check stops the whole batch, with the request and source IDs reported. [Autodesk NewDimension overload](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/475aab91-19d3-5884-d3eb-18dfc0d4004f.htm)
10. Compare each created dimension's ID and UID, owner view, type, line, ordered references and segment values. Read a two-reference dimension and a multi-segment string through their distinct native properties. Compare native values to independent expected segment values within 0.001 ft. Accept reversal only when the entire chain, adjacent pairs and segment values still match. Use the exact provisional commit event to check that the added ID set is exactly the read-back dimensions. Require complete events for the transaction in the reviewed document, zero modified or deleted IDs including the destination view and references, and zero other-document effects. The focus-view transaction and effect logic provide separate examples in `skills/am-safe-change/scripts/focus_view.py:170–222` and `skills/am-safe-change/scripts/focus_view_preview.py:156–174`. The dimension probe must enforce its own rollback boundary and stricter effect checks. Missing, incomplete or extra effects fail the trial while the group can still roll back. [Autodesk dimension members](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/210f88be-e3c5-26a4-7dd8-3296f6725cce.htm)
11. Always roll back the qualification group, including after a successful provisional audit. Independently query the saved host, destination view, source state and complete dimension inventory after rollback. Require the original baseline and absence of every provisional dimension ID. Record the payload digest, run ID, mode, decision, context, build and engine with the full event and readback records. A successful result qualifies only the exact fixture, reference strategy and runtime combination tested.
12. Keep persistence disabled until a native fixture proves the runtime can inspect exact effects after provisional commit while a rollback boundary still remains open through the real approval and Keep/Discard decision. Before enabling a real path, specify that verified boundary and prove it rejects missing or unexpected effects before Keep. The qualified persistent payload is distinct from the experimental one. Recheck context, ownership, view, references and exact effect scope on each attempt, with full dimension readback. Bind separate dry-run, Keep, Discard and repeat records to the same reviewed persistent payload and approved baseline. Independently verify actual kept dimensions and prove every provisional ID absent and the full baseline restored after Discard. A repeat after Keep must report the existing matches and add zero dimensions. If verification fails, restore the disposable baseline and retain the records.

## Acceptance and open questions

Use a saved Revit 2026 fixture with independently measured unequal grid bays and a rotated perpendicular grid string, two selected wall faces, and a door and window with different measured reference widths. Verify one successful native result per mode and check every measured segment against the corresponding reference pair. Include a mirrored opening with known planes and a missing or ambiguous reference that remains visible with source and reason. Reject oblique and out-of-plane placement, mixed unresolved extents, wrong type, shifted source geometry, stale view, duplicates, incomplete telemetry and a late failure after an earlier dimension was created. Prove full baseline restoration and absence of all trial IDs after rollback and Discard. Bind separate successful dry-run, Keep, Discard and repeat records as specified above. Record the Revit build, engine, revision and fixture.

The authorized Windows Revit host and representative fixture are external dependencies. Native grid reference form, mixed grid extents, family-reference witness geometry, measured tolerances and the effect boundary before Keep remain to be demonstrated. Curved or linked geometry, automatic dimension style changes and deletion of existing dimensions are outside the initial acceptance contract.

## Second-review implementation notes

- A native dimension curve can be unbounded. Compare the geometric support line, ordered witness stations, and paired native segment values. Require endpoint comparisons only after proving the native representation exposes corresponding endpoints. Include an unbounded or differently bounded readback in the repeat fixture.
- Bind the approved preview digest after the ownership check annotates it. Retain the separate versioned writer payload and compare its basis before mutation.
- A matching existing dimension is unchanged. Coalesce identical requests in the same batch. Block conflicting requests for the same placement.
