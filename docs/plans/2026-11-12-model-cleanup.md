# Review unused Revit items before cleanup

[Issue #140](https://github.com/zsenarchitect/archi-magic/issues/140) requests a preview of unused views, view templates, filters, scope boxes and CAD imports with their dependencies, followed by selected deletion through Keep/Discard. Sheet and template references must protect their targets. The gap is confirmed in `skills/am-model-health/scripts/model_health.py` at `check_views`. The current census measures viewports and schedule sheet instances. It supplies neither a reference graph nor a cleanup operation.

## Read-only inventory

Implement a separate `run_query` script in am-model-health so ordinary health checks keep their current runtime and output. For each supported element, return category, native decimal-string ID, UniqueId, VersionGuid, direct dependencies, incoming reference evidence and eligibility reasons. Pass a nonempty typed set of observed category IDs to `Document.GetUnusedElements` and match only the precise returned IDs. A Purge Unused result corroborates eligibility. Missing coverage or ambiguous identity leaves the item report-only. [Autodesk GetUnusedElements](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/dcb1f497-dfa6-bb3a-b9dd-f9a580f990f2.htm)

- Enumerate sheets, viewports, schedule instances and panel schedule instances. Protect placed views and schedules, their reference targets and their view-owned imports. Protect the active view, and every view with a primary or dependent relationship, including when neither view is placed or active. Resolve reference callouts, sections and elevations via `ReferenceableViewUtils.GetReferencedViewId`, following `skills/am-safe-change/scripts/duplicate_views.py`. Protect their targets even when those targets are empty and unplaced. Preserve all sources of a reference for the report. An unresolved relevant edge blocks eligibility. [Autodesk sheet placements](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/816db942-4e9c-7278-7f59-53048becc46a.htm) · [Autodesk reference view targets](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/055ef271-6d6f-1891-b8e4-275dbdeca9f9.htm)
- Protect view templates assigned by any view or as a default by any view family type. Protect filters attached to any view or template even when disabled. Distinguish inapplicable view APIs from read failures. Protect scope boxes referenced by view or datum parameters, including references originating from templates. Scan all relevant parameter owners for the relevant IDs. Record absent versus unreadable parameters separately. [Autodesk parameter IDs](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/fb011c91-be7e-f737-28c7-3f1e1917a0e0.htm)
- Start with a report-only inventory. The first view type to qualify for writes is DraftingView, with view-scoped collection guarded by IsViewValidForElementIteration. Sheets, schedules (including revision and keynote schedules), internal/system views and other unqualified types remain report-only. For the remaining classes, qualify View with IsTemplate, ParameterFilterElement or SelectionFilterElement, scope boxes in OST_VolumeOfInterest, and view-specific ImportInstance one by one. Missing exact native unused evidence stays report-only. Collect all view-owned content and inspect all relevant view-visible elements within budget. A missing, unsupported or incomplete iterator leaves the view report-only. Add an explicit intrinsic-content allowance only for concrete categories that native fixtures qualify. Existing model-health heavy-2D counts provide context.
- Reuse model health's `IsLinked`, `ViewSpecific` and `OwnerViewId` classification for CAD. Links, model-wide imports and unresolved owners remain report-only. Distinguish links, types and instances in evidence. Imported CAD eligible for deletion needs native unused evidence for its exact instance and affirmative evidence of no use in relevant views. Visibility-only use is sufficient to protect it. If the API cannot establish absence of view use, keep the instance report-only.

Set a cap of 5,000 scanned elements or edges per group and a 15-second soft deadline checked while collecting and before each costly query. A native API call can exceed the deadline. Report which groups are incomplete and block affected eligibility after overflow or API failure. A dependency reported by the API is evidence of a possible deletion side effect. The first write slice supports only dependency-free, unpinned selected roots. Bound traversal when recording a dependency chain, and report an incomplete chain as such. Direct dependencies, transitive or opaque dependency evidence, and a root whose native deletion cascades remain report-only.

## Selected deletion and verification

Ship the read-only inventory as its own slice. Enable a selected cleanup only after separately qualifying category-specific native evidence and the installed runtime policy on a disposable Revit 2026 project. Reuse the exact-set, failure capture and ownership checks in `skills/am-safe-change/scripts/warning_repair.py` and `warning_repair_preview.py`. Bind an explicit, nonempty selection to the saved project, active view, exact element identities, protected reference and surviving-element fingerprints, and current worksharing evidence. Require explicit selection confirmation before executing. Recompute evidence before both executions. Check effective ask policy and its request-time binding before each call. Dry Run uses both runtime dry_run:true and the script dry-run mode, and must return a complete rolled-back envelope bound to the plan, model and run. Read a fresh unchanged baseline and bind that evidence and the dry-run receipt to real apply. Any runtime auto-approval result requires immediate independent readback and leaves the outcome unresolved pending review. The planned deletion set is exactly the selected, independently eligible identities. Reject warnings, errors, added IDs, modified surviving IDs, extra or missing deletions, ambiguous event attribution, and incomplete or duplicate receipts. Require one attributed `DocumentChanged` execution receipt for each run and matching deleted IDs from `Document.Delete` and the event for the entire batch. Roll back on any mismatch before handing the real group to the runtime.

Read the project again after dry-run rollback, Discard and Keep. For rollback and Discard, prove selected and protected identities, fingerprints and reference edges survive. Worksharing borrowing can survive rollback. Reconcile and expose the exact expected `NotOwned` to `OwnedByCurrentUser` transitions, require their approval before real execution and reject unrelated or central drift. For Keep, verify exact absence of selected identities and protected reference and survivor fingerprints. Require the installed runtime's ask policy binding and genuine independent dry-run and real receipts before enabling Keep. No operations touch linked documents.

Native qualification requires a saved disposable fixture with eligible and protected examples from each supported category. Include a viewport, a regular schedule, a panel schedule, a reference view on a sheet, a template assigned only to a view family type, a template assigned by a view, the active view, a filter used by a template, a scope box referenced by a datum, a visible CAD underlay, an import owned by a sheet view, an unrelated CAD link and an element with a deletion cascade. Compare results with Purge Unused and view and sheet Properties. Trigger incomplete inventory, stale identities, a reference added between preview and run, shared and second-hop dependents, late failure and an unexpected native deletion. Test Dry Run, Discard and Keep plus post-operation readbacks. Worksharing requires a disposable central and two qualified users. Record each matrix row as qualified or report-only. Close #140 only after native Keep and protected controls pass for every promised category, or after the owner explicitly changes that scope. Release in this order: local checks, disposable Revit inventory and apply qualification, PR referencing #140, both exact-head CI jobs, merge and verification of the merged revision, then manual issue closure. The Revit project, runtime and users remain external dependencies. Revert the recipe commit to remove its entry point and use Revit Undo for an accepted disposable cleanup. Automatic or recurring purges remain outside scope.
