# Copy or combine instance parameter values (#161)

Base 3d3fdd74169440c9b2965632e5950c6cc66d6c02. GitHub #161 asks for category-scoped parameter copy or combination, previews of type mismatches, and a blocking warning for text-to-number. The current parameter checker reads parameters and sometimes resolves the first name match (skills/am-param-qa/scripts/param_qa.py:75–95). There is no parameter-copy recipe in skills/am-safe-change/SKILL.md:3,22–29. The parameter grid emits review-only changes with an empty steps list, so it cannot apply a typed copy.

## Flow and checks

1. Add the recipe to am-safe-change. Use one bounded, explicit category and optionally narrow it to a list of instance element IDs. Enforce the category on every ID and the read budget in skills/am-revit-api-docs/SKILL.md:289–298. Stop on an exceeded budget or missing explicit ID. Bind snapshots to a saved project with the existing project UniqueId and path digest pattern (skills/am-safe-change/scripts/focus_view.py:24–28). Bind rows to element ID and UniqueId. Leave element types, linked documents, family documents and mass type changes out of this instance recipe.
2. Copy uses one source parameter and one destination. Resolve each exact name using [Element.GetParameters](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/0cf342ef-c64f-b0b7-cbec-da8f3428a7dc.htm) and require one match. Retain Parameter.Id, StorageType, GetDataType().TypeId, HasValue, read-only state and exact typed value. For copy require matching storage and nonempty matching data type, a set source and a writable destination. Use raw doubles in internal Revit units, integers, strings and positive same-document ElementIds. Reject nonfinite numbers, unresolved element references and unsupported sentinel values. [Autodesk's Parameter guide](https://help.autodesk.com/cloudhelp/2025/ENU/Revit-API/files/Revit_API_Developers_Guide/Basic_Interaction_with_Revit_Elements/Parameters/Revit_API_Revit_API_Developers_Guide_Basic_Interaction_with_Revit_Elements_Parameters_Parameter_html.html) documents matching storage-specific reads and writes. Check supported Revit year API surfaces during review.
3. Combine accepts a bounded ordered list of explicit parameter-name or literal segments. For Level plus Number, a request can use a Level reference's display name, a literal separator and the Number value. Each parameter segment must resolve uniquely and have a value. Render strings directly, numeric values using a declared display policy and element references using the current document's element name. Require a String destination. Treat the request as data and evaluate no code or user expressions. Store the displayed inputs with the typed snapshot so stale presentation changes also invalidate a plan.
4. Compute outside Revit in a pure module usable by the agent's IronPython and the shell. Emit the normal change-preview with one row per element, ownership IDs for actual changes, and blocking warnings for missing or ambiguous fields, invalid storage/spec, unset sources or read-only destinations. Any blocking warning prevents the entire batch. Show unknown and unchanged rows in their correct states. Preserve exact text and decimal IDs. An approved plan records the request and a deterministic fingerprint of the source and destination state.
5. The Revit apply entry point reads the exact same request again, recomputes the plan, compares the fingerprint and meaningful plan output, and checks ownership before a transaction. Reject stale document, category membership, identities, typed values, referenced labels, ambiguity, and non-writable destinations. Use the matching Set overload and check its return. Regenerate and read back the expected values before committing the single transaction. Roll back on any failed write, regeneration or mismatch. Use the normal am-safe-change preview, ownership, dry run, Keep/Discard and post-Keep readback (SKILL.md:26–52). Report the final state from that workflow. To undo a kept run use its single Revit undo entry. To remove the recipe revert its merge commit.

## Acceptance and dependencies

Prove a category copy and a combination through the actual CLI and host entry point. Test text-to-number mismatch, numeric spec mismatch, duplicate names, an element type, a stale source and target, exact 64-bit IDs, false Set return, failed readback and rollback. Check blocked previews contain no executable changes. Dogfood the preview with the shared renderer and ownership helper. Use a disposable Revit model to compare typed values before and after, demonstrate the dry run does not persist them, and demonstrate Keep/Discard. Keep issue closure tied to evidence for the category copy and combination paths.

Dependencies are Revit and pyRevit for the native run and the existing offline Python and PowerShell paths. Review will confirm the API members and choose the simplest existing runner mechanism for shipping the pure module with the submitted script. Availability of a disposable Revit host is an external dependency for native verification. No schema migration or third-party package is planned.

## Detailed contract for review

- Limit the recipe to 500 retained instances, 5,000 scanned category members, 16 combine segments, and 2,000 characters per input field or combined result. Use a soft ten-second scan limit. Stop with no snapshot or partial plan on overflow. Bound the canonical ASCII JSON snapshot to 512 KiB while collecting. Verify the selected runtime can transport the largest supported result, or recover it from the full run record before computing. Do not infer completion from a truncated tool result. Confirm both explicit-ID and whole-category scope through the same read entry point. Include unchanged rows and complete category membership in the fingerprint.
- Target the existing Revit 2024–2026 ID path with System.Int64 and the IronPython-compatible module convention. Use signed decimal Parameter.Id and shared GUID where available. Require one consistent parameter definition identity per requested field across the batch. Compare the complete TypeId string conservatively. A direct copy needs matching nonempty data types. A combine input can use a positive ElementId for a resolved Level even when that built-in spec is empty. Record a referenced element's UniqueId, ID and resolved label. Use the documented name getter fallback in IronPython. For numerical combine segments use Revit's formatted value and block an unavailable representation. Explicitly dispatch the typed Set overload. Block grouped destinations and globally controlled destinations with an actionable warning. Scope recipe eligibility to instance parameters and disclose unsupported values.
- Follow recipes/focus-view.md:5 and focus_view.py:11 for the pyRevit workspace and local sibling imports. Wrap data in ASCII JSON as in focus_view.py:225–230. Support the bare and full run envelopes. Provide the same commands and read instructions as sibling recipes for baseline category and design-option counts, target ID hash, compute, comparison and side-effects. Use ownership.py inputs and check. Skip ownership and apply for blocked and zero-change results. Keep the reviewed immutable plan fields separate from ownership annotations. Reject an annotated blocked preview and validate immutable fields against a fresh read.
- Use the shared review-only renderer presentation for the display artifact to keep spreadsheet exports disabled. The display artifact has empty steps. The recipe retains a separate machine plan with typed steps and preview linkage. Describe the difference in the recipe docs. Bind that plan to the exact display preview and approved request. Test user text as inert HTML and ensure long IDs survive the renderer and ownership helper.
- Before both dry run and real run re-read live worksharing state for changed IDs. Follow focus_view.py:101–108 for the conservative allowlist. Use the Revit transaction as the write authority. Check Started and Committed states. Roll back only while Started and confirm RolledBack. Treat Pending and unknown status as unresolved. After RegenerationFailedException perform no document reads or retries. Reuse the error-handling pattern in focus_view.py:195–221. Test worksharing ambiguity, pending transaction, grouped target and membership drift before release.
- Return exact changed IDs and typed values so dry-run verification can compare them with the plan. Use lib/side_effects.py to show runtime totals and dependent categories. Stop if the expected changed IDs and values differ or runtime change evidence is unavailable. Show additional changes even when their categories match the edited category. Obtain approval through the existing am-safe-change flow when extra side effects are present.

Use explicit display labels for unset and empty text values so the viewer cannot collapse them into one state. Display enough precision to distinguish unequal numeric values even if Revit formats them identically. For direct ElementId writes, reject a destination data type that denotes a Family Type category or any unsupported special reference. Treat unavailable reference or ownership evidence as blocking. The user can choose an explicit smaller scope if these limitations apply.

### Operator sequence

Check context and policy, read the request, compute the preview, annotate ownership, and approve the plan. Run the runtime dry run with the same plan and read the complete run record with telemetry. Run a fresh query to confirm the original values still match the plan baseline. Check context and policy again before the real run. After Keep, read back exact approved elements and typed destination values. After Discard, confirm the baseline and follow the ownership hand-off. Verify one positive category copy and a Level-reference plus literal plus Number combination in the supported runtime. Verify a text-to-number case produces a warning on the intended element and starts no transaction. Simulate failure after an earlier successful Set and verify that the earlier value rolls back. Record the tested source revision, host year and engine, and exact observed before and after values in the acceptance receipt.

After Keep, compare values with the approved computed values. A combination can read its own destination, so never recompute it from the new state during verification. The changed baseline prevents accidental replay.
