## Align selected terrain vertices

Capture one native Toposolid and the requested existing vertices. Probe the existing `Selection.GetReferences()` and stable serialization pattern in `skills/am-model-health/scripts/inspect_linked_element.py:108–121` for exact host edge and face references. Use an explicit point manifest when selection cannot identify a vertex. A picked point supplies XY only. Resolve a single existing slab-shape vertex and record its own XYZ. Reject stacked/duplicate XY, a missing vertex, or multiple support mappings. Bind the document, terrain and support unique IDs, stable references and geometry signatures, selected and unselected vertices, explicit tolerances, and each approved result. Re-resolve these values before every write. Use internal feet for calculations and show the tolerance in project units.

For first qualification, project each vertex onto the finite XY projection of a nonvertical straight edge. Accept an endpoint only when it is the clamped closest point within tolerance. Reject off-end points outside tolerance and unsupported curves. For a selected pad, require exactly one vertical intersection with the trimmed top face, including holes. Preserve XY and verify the same vertices after regeneration and commit. Check selected vertices against actual 3D distance to the support and verify unselected vertices and the support did not change. Show points that need horizontal relocation or cannot be matched as excluded. Refuse to apply an incomplete requested batch. Require an enabled shape editor. On an isolated fixture, measure the documented elevation offset with a nonzero existing offset, a nonzero level and sentinel vertices. Use a rollback-only probe before enabling native apply.

## Create a floor from a selected region

Require an explicit native Toposolid region, floor type and level. Qualify complete sketch-bounded footprints and selected subdivisions separately. For subdivisions, resolve the parent and measure the selected subdivision's upper surface, including its offset, even when negative or zero. Bind subdivision, parent, sketch, surface, type and level to the approval basis. Refuse when top faces or sketch data are unavailable or cannot represent the selected region.

Carry exact closed loops and holes, and validate the native horizontal boundary and type eligibility. Follow `skills/am-safe-change/scripts/room_finish_placement.py:26–75` for type and level identity, profile validation and `FLOOR_HEIGHTABOVELEVEL_PARAM`. Verify the regenerated floor base with a fixture whose level is above zero and whose shared and model elevations differ. Rebuild grade using supported vertices and split lines. Insert distinct interior XY points and reuse existing boundary vertices. Refuse any region that needs an unqualified boundary split or unsupported curve.

Accept only a single-valued piecewise-planar top over XY. Reject vertical faces classified as top and positive-area overlaps in a projected mesh. Verify the source and floor cover the same XY region in both directions within approved tolerances, including hole locations and local missing strips or overhangs. Use exact supported boundary loops for boundary checks and projected coverage for interior validation. Evaluate maximum absolute elevation difference at every vertex of each overlap polygon of the two planar meshes. Confirm the approved type, level, base and source geometry and parameters from fresh reads. Roll back if any check fails.

2. Use the existing am-safe-change preview confirmation, model context, ownership and side-effect workflow. Bind normalized preview rows and exact freshness inputs to a digest. Keep `ownership_ids` to existing write targets and proven mutable dependencies. Include read-only support, source, type and level in the freshness basis. 3. Require the runner's native `ask` policy and validate policy, project, basis and ownership before each run. Bind the real request to that dry-run record. In both runs, verify before committing, then audit exact Revit document and transaction changes and reread committed geometry while the recipe group remains rollback-capable. For alignment allow the reviewed terrain and individually identified legitimate dependents. For conversion allow only the new floor and its proven sketch dependencies. 4. Let the outer runner present native Keep/Discard and require a separate real run ID with a user decision in its receipt. 5. Qualify the normal entry points for both requested operations on the disposable Revit model. 6. Publish with `Refs #167` when authorized. ## Read-only vertex inventory

On the disposable Revit 2026 fixture, use `get_context` to confirm the active model and call `run_query` on `skills/am-safe-change/scripts/read_toposolid_vertices.py` with `{"toposolid_id":"<decimal element ID>"}`. Save the complete query result. The inventory reports document and element identity plus existing vertices in internal feet. It preserves duplicate XY coordinates for later ambiguity checks. Its provisional bounds are 2,000 vertices, five seconds of observed read work, and a 256 KiB response. A stopped result carries no partial snapshot. Native reference capture, terrain conversion and model writes require separate implementation and fixture checks.

The read query also accepts an optional `alignment` object with `points_xy_ft`, `support_reference` and `tolerance_ft`. Supply up to 100 XY pairs and one stable reference to a straight edge or upward-facing planar support in the active project. A point with missing, ambiguous or repeated vertex identity or outside the support marks the batch blocked. Rows show before and proposed coordinates in internal feet. Support inside linked elements and family instances is refused pending coordinate qualification. This query computes candidate geometry without opening a transaction. The selection path still needs live qualification. A production apply path and floor conversion remain pending.

## Read-only floor region inventory

With the scripts directory as the query workspace, call `run_query` on `read_toposolid_floor_region.py` with decimal-string `region_id`, `floor_type_id` and `level_id`. Save the full result. The region may be a Toposolid or a subdivision that exposes its own sketch and top faces. The result records the sketch loops, bounded line and arc geometry, top-face triangles, destination type and project elevation, and any subdivision parent and offset. Revit tessellates the top faces. The snapshot alone does not establish that the mesh covers the exact profile or that a floor can reproduce it. The fixture still needs to verify sketch and face access before conversion.

For a candidate floor, call the same read query with only `floor_id`. Save that independent result and compare the two top meshes with `python3 toposolid_grade_check.py source.json floor.json --area-tolerance-sqft <approved area> --elevation-tolerance-ft <approved elevation>`. The checker measures coverage separately in each direction and checks the maximum elevation difference at the intersection polygon vertices. It refuses overlapping or discontinuous triangles within a mesh. Exit 0 means both meshes meet the supplied limits, exit 1 reports a mismatch, and exit 2 means the comparison stopped. For floor verification, also pass `--xy-tolerance-ft <approved XY distance> --expected-floor-offset-ft <reviewed offset>`. This checks the actual floor type, level and offset as well as sketch loops. It accepts reordered loops and reversed or rotated traversal of the same bounded curves. For arcs, the check bounds the difference along the full sweep using the native center. Capture fresh readbacks containing that center. This command verifies the two supplied readbacks. Native model-write receipts and independent source rechecks remain part of the apply workflow.

## Rollback-only vertex offset probe

Use an authorized disposable, saved, local non-workshared Revit 2026 model. Choose a Toposolid on a nonzero project level with an enabled editor, one previously offset vertex and at least one untouched vertex. Run the read-only vertex inventory, confirm the active document and review the exact vertex and two test offsets. Pass the decoded inventory as `baseline`, the exact recorded XYZ as `vertex_ft`, and the two distinct test values as `offsets_ft`. Run `probe_toposolid_vertex_offset.py` through `run_modify` with `dry_run: true`. The script rolls back its own transaction even when measurement fails. It checks all recorded vertices after rollback. Save the runner receipt and use a separate read query to confirm the full baseline again. A measured result documents one fixture and build. Production alignment still requires applying and verifying the approved target geometry on qualified cases.

## Rollback-only floor conversion probe

On the authorized disposable local fixture, obtain a fresh source readback from `read_toposolid_floor_region.py`. Review the source geometry, destination level and type, floor offset, and explicit tolerances. Run `probe_toposolid_floor_conversion.py` with `run_modify` and `dry_run: true`. Pass the decoded source snapshot as `baseline`, and supply `floor_offset_ft`, `xy_tolerance_ft`, `area_tolerance_sqft`, `elevation_tolerance_ft` and `shape`. For a flat fixture, use empty lists for `shape.boundary_ft`, `shape.interior_ft` and `shape.split_lines_xy_ft`. For a shaped fixture, choose reviewed source mesh XYZs for existing boundary vertices and strictly interior new points. Give each split as two source XY pairs that should resolve to native vertices. The probe reconstructs the closed profile, sets the offset, applies the selected shape operations and compares the candidate readback. It then rolls back and verifies that the floor is absent and the complete source readback matches the baseline. Capture the runner receipt and independently reread the source. A measured result qualifies only the exercised fixture and Revit build.

To derive the probe's shape from a saved terrain query, run `python3 toposolid_floor_shape.py source.json --floor-offset-ft <reviewed offset>` and review the output before passing it as `shape`. The planner retains crease edges where neighboring triangles describe different planes and omits coplanar tessellation edges. It verifies that the mesh boundary follows the native sketch. It stops when a grade break needs a boundary vertex the sketch cannot supply, the mesh does not match the sketch, or the fixture exceeds the probe limits. The native probe still verifies the resulting floor against the original source.

The alignment query can read the active Revit selection. Omit `support_reference` to use exactly one selected native edge or face. Omit `points_xy_ft` to use terrain references with Revit-reported point coordinates. The query uses only their XY and retrieves the original elevation from the actual shape vertex. If Revit does not provide a point for every terrain reference, supply explicit XY values from the inventory. Save the resolved `alignment.request` from the preview so later checks can reread the same reference and points without depending on a changed selection.

After recording the single-vertex offset measurement, run `probe_toposolid_alignment.py` on the same authorized disposable fixture with `run_modify` and `dry_run: true`. Supply the complete reviewed alignment snapshot as `baseline`. The probe rereads the resolved support and target points, measures the zero-offset elevation for each changed vertex, and verifies the proposed elevation and distance to the original support. It stops on changes to any other vertex or to the support. Save the full bridge records for the original query, probe, and independent fresh query. Run `python3 skills/am-safe-change/scripts/verify_toposolid_alignment.py before.json trial.json fresh.json`. Require `toposolid_alignment_rollback_verified`.

## Review artifacts for the fixture probes

Run `python3 toposolid_preview.py alignment query.json preview.json > probe-input.json` for a saved alignment readback. For floor conversion use `python3 toposolid_preview.py floor query.json preview.json --floor-offset-ft <offset> --xy-tolerance-ft <XY limit> --area-tolerance-sqft <area limit> --elevation-tolerance-ft <elevation limit> > probe-input.json`. Open `preview.json` in the standard am-safe-change renderer and review the rows and ownership before running the appropriate probe. Exit 1 records a blocked preview and emits `null` in place of probe inputs. Exit 2 means the preview could not be built. Only use probe inputs from a successful preview and its approved disposable fixture. The probe re-reads the exact baseline before opening a transaction.
