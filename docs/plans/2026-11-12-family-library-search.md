# Search the Revit family library and place a reviewed type (#153)

[Issue #153](https://github.com/zsenarchitect/archi-magic/issues/153) requests a library index, search by name, category and parameter, path and thumbnails in results, and reviewed loading and placement that reuses an existing project type. Baseline `0c523067c4313bd9e8c3898be4ffd32d874463d7`. [The manufacturer import skill](../../skills/am-import-from-manufacturer-rvt/SKILL.md) copies system types from open RVT models. This workflow targets loadable RFA families and uses the [safe-change workflow](../../skills/am-safe-change/SKILL.md) for project edits.

## Index and search

1. Accept one explicit library root in a local folder or an approved Autodesk Docs folder available on the workstation through Desktop Connector. Discover regular RFA files under the selected root only. Require the user to make the Docs files available locally before reading. Skip unavailable files, aliases, links and unresolved paths with an explicit reason. Reuse the local-path and metadata checks in `skills/am-model-health/scripts/cad_file_inventory.py:24–39` and the stable-copy checks in `skills/am-model-health/scripts/batch_model_audit.py:44`. Bound scans, depth, file count and bytes. Test which connector file attributes identify hydrated files without opening a cloud placeholder. [Autodesk Docs file availability](https://help.autodesk.com/cloudhelp/ENU/CONNECT-User-Guide/files/Files_Folders_Docs.htm)
2. Stage content-addressed private copies of reviewed files and verify their hashes before native reads. The index stores root-relative paths, byte hashes, Revit build, family/category identity, embedded type names and selected typed parameter values. Use a disposable Revit worker to open each staged family and read the FamilyManager types and supported type values. Close without saving after each family. If a file depends on a type catalog, report its scope explicitly. Support its types only after qualifying a paired, pinned RFA/catalog read and keeping their base filenames intact in the private staging directory. Report partial and unreadable coverage separately from a complete index. [Autodesk FamilyManager](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/1cc4fe6c-0e9f-7439-0021-32d2e06f4c33.htm) · [Autodesk FamilyType](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/7f15b213-c99b-db59-3622-3280757b82d9.htm)
3. For thumbnails, qualify `ElementType.GetPreviewImage` on the exact symbol loaded into a disposable scratch project with no production model open. Save a bounded PNG locally, dispose the bitmap and close the scratch project without saving. Bind each thumbnail to the RFA hash and exact type. If the API returns no bitmap, report that result explicitly and retain the searchable type. Assess the reviewed family-thumbnail workflow if it lands before adding a second rendering path. [Autodesk ElementType.GetPreviewImage](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/e79da134-713a-2202-4898-cca930202dff.htm)
4. Use a bounded, versioned local index with one row per exact file and type. Keep indexing and search usable without a running Revit instance after enrichment. Normalize search text for name/category filters. Match parameters by stable identity where available and retain original typed values, unit metadata and display text. Surface ambiguous parameter names and incomplete index coverage. Return exact family and type, category, path, and a local thumbnail reference or its unavailability. Keep duplicates across folders distinct. Refresh only changed or missing entries, invalidate thumbnails when the source changes, and replace the saved index atomically. The original files remain unchanged.

## Load and place a reviewed type

5. Read the saved host project and exact selected library record. Match existing native symbols by the reviewed family, category, and exact type name. If exactly one exists, bind its IDs and UIDs and present reuse in the preview. Compare any reviewed parameter differences before the user approves. Stop on ambiguity. If the type is absent, use one validated staged source whose bytes match the selected result. Try the `LoadFamilySymbol` overload with explicit no-overwrite policy in a disposable fixture. For a family already present with another type, verify that adding the selected type preserves its siblings and project overrides. Confirm callbacks, transaction requirements, and load results in the actual Revit bridge before supporting Keep. [Autodesk LoadFamilySymbol with load options](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/255f2e8c-8990-8617-7f16-a77915b8a52e.htm)
6. Bind the project, selected source digest or existing symbol, reviewed level, point, rotation, placement type and any required host. Start native qualification with point-based one-level families using the existing level-based placement pattern in `skills/am-floor-drain/scripts/place-floor-drains.py:299–309`. Report hosted, face-based, adaptive and other unqualified placement categories without attempting a fallback. Reread source, symbol, host and ownership immediately before each mutation. Use a separate versioned apply payload. Show load versus reuse and all intended model effects in the existing review-only preview.
7. The first native attempt is in a saved disposable project under ask policy. Verify context, ownership and exact approval before `dry_run: true`. In one transaction inside a reversible group, load only if needed, activate only the reviewed symbol, place and regenerate. Read actual symbol, level/host, location, angle and instance UID before provisional commit. Audit the exact additions and modifications before releasing rollback. Reuse must leave the library definition and existing instances unchanged. A load can add reviewed family definitions and required dependencies. An unreviewed overwrite, document effect or unclassified dependency blocks the attempt. Roll back on failure or ambiguous evidence. Keep remains pending until native effect evidence is available while rollback is possible. Save separate complete dry-run, Keep and Discard records and independently verify each result.

## Acceptance and dependencies

Use a controlled folder with duplicate filenames in different folders, multiple types, selected text and numeric parameters, a missing thumbnail, and a stale file hash. Confirm exact search results and correct paths and thumbnails. Check the same expected result from a locally available Docs fixture and explicitly report unavailable files. Native controls must show both reuse of a previously loaded symbol without a reload and loading a missing type while preserving existing types. Verify instance pose and identity after Keep. Verify full baseline restoration after Discard and a forced late failure. Record the exact branch revision, Revit and connector versions, fixture scope and full receipts.

The approved Windows Revit host, a disposable project, and an authorized Docs fixture are external dependencies. Native thumbnail support, type-catalog coverage, no-overwrite load callbacks, connector hydration detection and complete pre-Keep effect visibility remain to be measured. Direct cloud API indexing, new credentials, system types, editing originals and automatic replacement of project family definitions are outside the initial workflow.
