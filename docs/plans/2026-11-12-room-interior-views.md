# Room interior elevations and sections for issue #160

[Issue #160](https://github.com/zsenarchitect/archi-magic/issues/160) requests interior elevations for selected rooms, cropped to each room, with a template and names from the room number. The title also names sections. Make elevations for the reviewed room sides and allow explicitly reviewed section cut lines. Use a compatible template for each view family. Source baseline is `0c523067c4313bd9e8c3898be4ffd32d874463d7`. The backlog audit and baseline source search found a room-boundary reader, detail-view creation and plan crop support. No existing recipe combines them into room interior views.

## Compute and show the view set

- The offline planner emits a standard `change-preview` with `review_only: true` and `steps: []` with room number, intended view name, source side or reviewed section line, template, view direction, crop dimensions and far extent. Display exact names using the room number and explicit stable suffixes. Supply a naming rule up front if room numbers collide or contain invalid characters. Deduplicate only geometrically identical requested views. Keep geometry, source identities and parameters in a digest-bound private proposal. Compute all room rows before mutation. Bound qualification at 20 rooms, 12 requested views per room, 80 total views, 2,000 boundary or solid visits, 20,000 native name collector visits, 20,000 geometric intersection pairs, 80 markers, 160 tracked additions, 2 MiB each for request and emitted evidence, and a measured 30-second preparation budget. Abort before mutation when the planned scope exceeds a limit. Abort and roll back the trial if effects or detailed readback exceed the measured safe limit or arrive truncated. Exercise exact-cap and one-over cases, including a high-view-count project and a large room boundary. Confirm practical bounds on the installed bridge and its detailed effect-list limit before sizing a write batch.
- Elevations use `ElevationMarker.CreateElevationMarker` and `CreateElevation` with a reviewed host plan and a verified free index. Prefer one qualified marker for a room when the side directions align with its available indices. For a non-orthogonal side use a dedicated marker. Define look as the signed vector into the model from the marker toward the selected finish face. Revit ViewDirection points toward the viewer. Use the measured signed angle around host Z, regenerate, and require the normalized ViewDirection to agree with negative look within the approved tolerance. Establish the sign with an asymmetric fixture containing a target in front and a control behind the marker. Never infer a direction from the slot index. Verify marker positioning and exactly one intended elevation per eligible side. [Autodesk ElevationMarker](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/ca59d2f7-4cd0-d13d-22a0-c153ac8310d4.htm)
- Sections use the explicitly approved vertical cut plane derived from a straight model line and a selected look direction. Construct a right-handed orthonormal `BoundingBoxXYZ` with both bounds enabled on each axis. `CreateSection` assigns view direction from BasisZ and up from BasisY and derives its own right vector. Treat input BasisZ and the creation-time Z span as host API inputs to qualify. Require the native ViewDirection to agree with negative look and verify the world cut-plane origin and measured depth independently using an asymmetric fixture with geometry on both sides of the cut. Read the actual native frame after creation. Crop to the measured room slice and set the reviewed far extent. Reject a cut that leaves no measurable room slice. [Autodesk CreateSection](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/d6228f68-3643-8aaf-72bb-f9a0b4125886.htm)
- Apply an explicitly compatible template without changing the template. Call IsValidViewTemplate on the actual created view. Compute controlled IDs by subtracting the non-controlled IDs from the template parameter IDs. Block when a controlled setting needs a change to meet the reviewed target. Independently read back effective phase and design-option visibility after applying the template, including settings inherited from the elevation host plan. Set the crop in the actual native view frame after template assignment and regeneration. Compute min and max from the measured target face or slice and a reviewed padding value. Use GetCropRegionShapeManager to verify one active unsplit rectangular model crop with the expected vertices in the actual view frame. Block nonrectangular crops, split crops and active scope boxes. Read back far-clip mode and finite offset separately, along with view direction, template, scale and exact name. Include compatible controlled and uncontrolled template settings and a conflicting-template control. Check for adjacent rooms intruding into the crop or view depth.
