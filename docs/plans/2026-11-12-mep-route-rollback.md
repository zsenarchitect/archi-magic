[Issue #186](https://github.com/zsenarchitect/archi-magic/issues/186) calls for reviewed route previews and Keep/Discard. Filed gap confirmed at `716f02f3c6c03549c130ffca8b33cb16ccb14ba2`. ## Trial scope and sequence

1. Bind the reviewed endpoint, obstacle, elbow, routing-area and preview inputs to the exact disposable project. Require saved standalone Revit 2026, active writable local fixture, explicit fixture confirmation, same-document open endpoints, matching round profiles and no worksharing. Read exact curve, system type and level IDs with UIDs and verify their classes before opening a group. Require one reviewed host obstacle inventory, or explicitly reviewed empty obstacle scope. Re-read link identities and selected obstacle bounds when supplied. The first experiment covers round duct and pipe routes. Rectangular and oval, cable tray, conduit, transitions, sloped runs, worksharing and native Keep remain separate work under the same epic.
2. Recompute the reviewed path with the pure preview. Run an outer abortable transaction group and one inner transaction, following the existing color trial and transaction event checks. Use the official point-to-point duct or pipe constructor with the exact system, curve type and level. Set and re-read the correct diameter before trying to connect. Identify each new curve's two connectors by reviewed points and axes. Use `NewElbowFitting` at each reviewed bend. Use `ConnectTo` at the two original ends. The endpoint API can add fittings. Abort if the complete native change set contains anything beyond the exact new segments, the reviewed elbow at each bend, and the two reviewed owners. Verify both logical and physical references only as needed to establish the physical chain. [Duct creation](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/86174dcb-e86e-c987-93ff-75e3d2773cf0.htm) · [Pipe creation](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/9550265f-5760-3c28-d023-d0373285855b.htm) · [Elbow creation](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/6f206b7d-f982-bdbd-8342-ed99719e9d81.htm) · [Endpoint connection](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/04ee99c9-f411-aabe-7b87-013a6f9adb1d.htm) · [Rollback example](../../skills/am-safe-change/scripts/probe_color_legend.py)
3. After inner commit and before rollback, independently enumerate both ends of every created segment and elbow. Verify type IDs and UIDs, reviewed size, finite transformed geometry, expected physical neighbor identities, and measured 45 or 90 degree bends. Endpoints must connect directly to the intended reviewed owner and connector. Measure elbow and segment bounds against the reviewed obstacle boxes and clearance. Exact planned centerline segments may be shortened by fitting insertion. Fail closed for any unreviewed displacement, incompatible envelope, wrong elbow, unexpected connection, unresolved bounds, missing telemetry or late event. Bound native visits, receipt size and number of elements so the loaded bridge can return the complete change IDs. Never present a centerline check as solid fitting clearance.
4. Always roll back the group. Check native final state, reread exact original open connectors and obstacle records, and confirm every created ID is absent. Capture a separately retrieved full bridge response and a fresh query for independent comparison. A failure to establish rollback is unresolved. Neither the script nor the user workflow saves the trial document. Repeat with a successful straight route and both bend angles, a deliberately unqualified elbow, a blocked envelope, a stale owner/link, injected mid-route and late changes, and a disconnected or unexpected branch. Measure zero residual elements and restored connector states. No closure until the other MEP phases and the native Keep/Discard workflow are independently qualified.

## Assumptions and external dependencies

| Assumption | Check before claiming the result |
|---|---|
| Loaded Revit exposes the documented constructors and correct diameter parameter for each class. | Check documented API members and verify actual created sizes in a disposable host for both domains. |
| The preferred elbow family can be placed at each reviewed bend angle. | Compare the actual symbol and measured connector-axis angle after placement. The preference lookup alone is insufficient. |
| Revit may trim curve endpoints or create unexpected systems and fittings. | Inspect actual post-commit graph and exact change IDs. Stop on unexplained changes or geometry outside the reviewed route. |
| Revit may defer change notifications or leave a transaction pending. | Measure commit events and final transaction states. Require complete bridge records and an independent post-rollback read. |
| Supplied obstacles cover the reviewed route area. | Record the explicit scope, re-read boxes, and test the resulting element envelopes. The operator must confirm obstacle coverage on the disposable fixture. |

The licensed Windows Revit bench is currently offline. The exact pyRevit build, approved disposable model and fitting catalog are needed for native execution. Revert the isolated probe and tests to remove the experimental command. The probe does not introduce production writes, automatic system assignment, persistence, or a Keep path. The remaining model-write workflow needs a host policy that enforces a user decision.
