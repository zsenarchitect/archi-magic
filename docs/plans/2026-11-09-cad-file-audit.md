# Read-only audit directly from CAD drawings (#188 phase 1)

Baseline main 53ee6e0bcf51057976687bcc651815ff8aa8c9f8. The issue and RFC 001 require direct layer, external reference, block/attribute and units audits. Filed gap confirmed at dwg_cad_audit.py main: the real CLI takes pre-extracted JSON, and its findings never inspect the source drawing. A synthetic AutoCAD 2000 DWG seeded with layer NonStandard and Xref relative/missing-reference.dwg was decoded by LibreDWG 0.14 dwgread -O JSON with exit zero and the exact native block-header Xref flag and path. The same DWG passed through dwg2dxf with exit zero but lost its Xref flag and path. Reproduce both mechanisms and use native metadata for DWG, not a DXF conversion of unknown fidelity. RFC 001 identifies local headless parsing for this phase. Keep the existing JSON audit entry point and add direct .dwg and .dxf arguments.

1. Read regular local drawings only. Freeze a size-bounded snapshot and digest it. For DXF, use trusted optional ezdxf 1.4.5 and its local readfile parser in a bounded subprocess. For DWG, require the operator's explicit trusted absolute LibreDWG 0.14 dwgread executable; invoke in a private temporary directory with a controlled input filename and no shell or stdin. Do not install or download tooling, invoke AutoCAD, pass embedded names into a command, or follow hyperlinks. Use actual signature, exit code, output size, time, recognized JSON sections, decoder error reporting and declared format to refuse unsupported or degraded reads. Report decoder and source SHA256. Qualify initially on a synthetic R2000 sample and declare the accepted version scope rather than extrapolating. No writes to input and no external dependencies in JSON mode.
2. Extract layer and element counts, definitions and actual insertion counts, attached per-instance attributes and defaults where applicable, Xref flags/path and drawing unit settings. Use handle identities in native records, preserve actual source names and avoid treating absent fields as observed values. One-level Xref checks use literal relative paths under the chosen drawing directory, verified regular local files only. Do not read child drawing contents or look at network, drive-root or escaped paths. Report an untested Xref scope with explicit status; prove a self-reference on an existing local path, and leave nested-cycle analysis explicitly deferred unless scoped graph traversal has independent acceptance. Report reference paths as local output only. Keep findings and counts bounded. Use the existing audit findings/rule IDs; make extraction limitations and coverage visible. Unknown checks cannot produce an unqualified green.
3. Run direct CLI on native seeded DWG and DXF and on a clean file. Verify nonstandard layer and missing Xref exact, block and attribute inventory, source digest unchanged, and valid positive controls. Cover symlink/UNC/escaped Xref, malformed decoder results and missing tools, no silent downgrade, bounded decoder execution, and no outputs written on invalid input. Maintain old JSON behavior. Tests should use genuine DXF and synthetic DWG bytes with vendor binary acceptance outside CI if not installed. Do not commit third-party binaries or rely on a proprietary converter for test setup.
4. Keep #188 open after this contribution. Phase 2 still needs native AutoCAD .NET preview/rollback/approval on disposable DWGs and independent post-save readback. Phase 3 still requires #166 mapping and verified round trip, including DWG units and coordinates. Roll back this phase by reverting its merge; it writes no source drawing. Read-only report output is new local path or the existing JSON mode behavior. No viewport automation, no external network search, no layer standards claims beyond the existing rule set.

## Reviewed implementation and acceptance contracts

- Update RFC 001 to record the tested direct reader addition and the observed conversion loss. The product takes explicit optional tools only. For DXF use ezdxf 1.4.5 through a local readfile worker, for DWG use an operator-selected absolute dwgread 0.14 binary. The R2000 (AC1015) and public 2018 (AC1032) controls qualified the JSON schema; accept those signatures only, fail clearly for others. Confirm command format with installed --help and require exact source version in the decoded report. Do not send Xref or other auxiliary paths to either decoder. Work in a new isolated temp folder. Both decoder commands read one file and extract stored metadata; neither calls a reference loader or an embed operation. Run offline and compare before/after digests of the original. Capture bounded output during execution with concurrent readers, hard byte budgets, a wall deadline, child kill and reap. Limit inputs to 32 MiB, decoded stdout to 32 MiB and stderr to 128 KiB. Bound object counts, string length and JSON depth. Report generic failure and status without raw stderr. Fail on real decoder errors even with exit zero. A synthetic DWG proves native format readback and seeded results. It does not establish an AutoCAD-authored or AutoCAD-saved sample.
- Source path comes from the operator. Reject URI, UNC, device, drive-relative and symlink leaf paths before opening; open a regular handle with no-follow where supported, stream once into a private file, and hash the copied bytes. Use a stability check and same snapshot for format identification and parsing. Operating-system network mounts on an otherwise local path cannot be recognized uniformly. Keep Xref traversal lexical until validated: reject either slash style of absolute, drive-relative, UNC, device, traversal, and unsafe component names. Inspect each component with lstat and reject links and reparse points, including intermediate ones. Use only the drawing's original local directory, never the temp folder. Check existence of a regular file without opening any referenced drawing. Distinguish present, missing, self and unchecked. Native report uses stdout or an exclusive new local output path. A decode or schema error writes no result, and a previous output stays intact.
- DWG schema: FILEHEADER.version, HEADER.INSUNITS and Template.MEASUREMENT. For BLOCK_HEADER use blkisxref or xrefoverlaid and xref_pname, report inconsistent path/flags, never use is_xref_ref alone. Index 3-slot object handles and use the 4-slot absolute reference id (not the encoded third slot) for insert, layer and attribute relationships. Preserve block definitions, explicit reference counts and raw attribute/definition records. Associate native values only when ownership or a verified native handle chain establishes it; keep unassociated records visible, show incomplete status for unresolved relationships, and do not silently substitute a block default. DXF use block.is_xref/is_xref_overlay, INSERT.attribs and distinct ATTDEF records. Export counts and optional zero-insert block candidates without claiming purge safety. Do not infer required tags from definitions or classify unknown units as loaded. Preserve the existing JSON CLI for all other suffixes and the 0/1 output contract. New direct mode uses the same audit rules with an inventory and coverage envelope. CLI exit 2 indicates an invalid or unavailable decode, and 3 indicates valid output with incomplete applicable checks. A report with known findings and gaps contains both. Color and linetype inventory is distinct from checking an office policy. Nested Xref graph/cycles, deep purge eligibility, cross-platform AutoCAD authoring, and unsupported versions remain explicit gaps and keep applicable coverage incomplete.
- Pin reproducible acceptance inputs. The seeded R2000 DWG was made from a local ezdxf R2000 file with NonStandard and missing-reference, converted by dxf2dwg and repaired for the fixture with dwgread JSON setting the block header blkisxref and xref_pname before dwgwrite --as r2000. Its SHA-256 is da4324bcbd7ddabb33039e6d50827acbfe9190c5e9c77b09f388ea5ba364158b. Positive control is LibreDWG tag 0.14 test/test-data/2018/Line.dwg, SHA-256 1f4edd4c11aaf28b3295fd69fa59376f9cb911c637aa47a6073408ecac4797a3. Neither third-party tooling nor fixtures need to ship. Record exact release, flags, results, source hashes and coverage. Phase 1 seeded DWG acceptance is separate from all Phase 1 audit coverage, Phase 2 approval proof and Phase 3 handoff. Leave #188 open.

## Local acceptance receipt

The direct CLI detected NonStandard (CAD-LAY-01) and missing-reference (CAD-XREF-01) in the seeded R2000 DWG and marked nested Xrefs unchecked (exit 3). The independent AC1032 file decoded and audited with zero errors (exit 0). The file digests before and after both runs matched the fixture hashes above. The direct DXF test checks distinct attribute definitions and inserted values, the drawing digest, and preservation of an existing output file. Native JSON repeats unused type, _subclass, and blank-name metadata in these fixtures; the parser permits those metadata repetitions and rejects duplicate consumed fields.

## Composite R2000 policy audit

A binary R2000 fixture combined two title-block inserts, a blank required attribute, a nonstandard layer, mismatched layer color and linetype, a missing saved Xref, and mismatched insertion and pattern units. LibreDWG 0.14 exposed the attribute values but omitted their owner fields. The INSERT records retained first/last attribute handles and owned SEQEND records, and the BLOCK_HEADER retained its definition chain. On the same DWG, the original audit exited 3 with both insert-tag checks unverified. The revised audit exited 1 with two completed checks and one blank-attribute finding (CAD-BLK-02 on insert 58). The layer, Xref and unit findings were retained. The drawing SHA-256 remained `5a414a1c9ad56592f5255f4a4f9a9aacb0151f09a305328c57f6b7165691d17a`. Local tests also reject a wrong SEQEND owner, a broken chain and attributes claimed by two inserts.
