# Create levels and grids from a list (#169)

Base 0c523067c4313bd9e8c3898be4ffd32d874463d7. GitHub #169 asks for levels from named spacing rows and grids from repeated spacing strings, with existing names reported instead of duplicated. The current backlog ledger identifies datum creation as pending (docs/plans/2026-11-09-backlog-delivery.md:45). am-safe-change provides a read, compute, approval, dry-run, apply and verify contract for new recipes (skills/am-safe-change/SKILL.md:22–52). Its focus-view recipe demonstrates creation-only preflight and telemetry (skills/am-safe-change/recipes/focus-view.md:5–12).

1. Read existing levels, grids and multi-segment grids in a saved host project. Record exact IDs, UIDs and names. Read each existing level's ProjectElevation and type for display. Bind the snapshot to project UID and path digest as in focus_view.py:24–28. Use bounded native collectors and return a complete ASCII JSON snapshot, or report incomplete scope. Never create or alter a datum during read.
2. Take one request with explicit units mm, m, or ft. A level row has a name and either absolute elevation or positive spacing from the previous row. The first row needs an elevation. A grid run supplies an axis X or Y, an initial coordinate, two perpendicular extent endpoints, a spacing string, and exact names in order. An X run steps along the internal X axis and draws parallel Y lines. A Y run does the reverse. Coordinates use project internal axes and grids lie on Z=0. Parse comma-separated distances and count x distance terms such as 3x8000, 2x6000. The sequence names the start line plus one grid per interval. Validate numbers and bounds before expansion. Use Decimal arithmetic and convert to internal feet once.
3. Compare names case-insensitively within the level or grid family. Include multi-segment grid names in the grid family. Report existing names as skipped with IDs and existing details. Create other reviewed rows. Block repeated requested names in the same family rather than assigning an ambiguous position. An all-existing request reports a no-op. Repeating a successful request must not add any datum. Show requested project elevation or grid endpoints and all skipped rows in the standard change-preview. The machine plan contains only new datums, with exact snapshot and request linkage. There are zero existing write targets.
4. Use one native transaction after am-safe-change review and dry run. Re-read the project inventory and recompute immediately before applying. Reject a blocked preview, stale target or name inventory. Use [Level.Create](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/d661b7cd-dec8-6ae6-a753-b14ac2568772.htm), [Grid.Create](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/462cb588-9811-e464-0fe9-13226a2fc8f7.htm), bound lines and the native short-curve tolerance. Set names only on newly created datums. Regenerate and read back [Level.ProjectElevation](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/895ef506-bfea-cc4e-31f8-aad2af6672e4.htm), grid geometry, names and identities. Roll back if they disagree. Verify transaction state. After regeneration failure perform no further model reads. Undo the single kept operation to revert it.
5. Read the full dry-run record and require exactly the planned new datums, no unrelated modifications, deletions or changed documents. Confirm the original inventory is unchanged immediately after dry run. Check policy and use Keep or Discard through the existing am-safe-change flow. After Keep read back the exact created IDs and UIDs and compare with the plan. After Discard verify the original inventory. Test name collisions, invalid or overlong spacing, mixed units controls, known axes and extent, stale snapshot, partial failure rollback, exact telemetry and repeat behavior. In a disposable model compare directly with existing names, elevations and grid intervals in native Revit before closing #169.

Dependencies are supported Revit 2024–2026, the existing pyRevit runtime and shell Python. No package or data migration. The disposable Windows Revit host is an outstanding dependency for native acceptance. Revert the code PR to remove the feature.

## Reviewed implementation details

- Limit request bytes to 64 KiB, names to 100 characters, levels and expanded grids together to 500, grid runs to 20, spacing terms per run to 100, and the full inventory to 10,000 rows or ten seconds. Keep the complete ASCII snapshot within 2 MiB. Check repeat and cumulative counts before expansion. Accept signed finite plain decimals of at most twelve digits and six decimal places. Reject coordinate magnitude above 30,000 internal feet, collapsed offsets, zero-length extents, and nonpositive spacing. Normalize reversed extents. Also check native XYZ design limits and ShortCurveTolerance before starting the transaction.
- Read the displayed MultiSegmentGrid.Text as one logical grid name. Use GetGridIds to exclude its child segments from standalone grid inventory, and retain their IDs with the parent. Use Grid.Name and Level.Name for standalone datums. Include every colliding ID in diagnostics. Report coordinate differences on skipped existing names. Skip a name match without altering its geometry. Show a distinct-name geometric coincidence in the preview without treating it as a forbidden name.
- Keep the named spacing coordinate frame explicit. Levels use project-origin elevation. Grids use internal model XY at Z=0. Check levels against ProjectElevation and line endpoints independent of direction within 1e-6 ft. Validate permitted names before creating where NamingUtils.IsValidName is available, and use native Name assignment as the authority. Roll back on late conflicts. Require exact transaction status and roll back only while Started. Treat Pending as unresolved.
- For the native acceptance model, use a displaced project base point or shared elevation display. Independently inspect ProjectElevation and check that no plan views were created. Include a multi-segment grid name collision, a spacing run with both repeat terms, an unchanged repeat, and Keep and Discard controls. Compare the full dry-run telemetry to the exact returned datum IDs. Read the actual kept run IDs and UIDs separately. Test at-budget and over-budget inputs, cumulative overflow and late rollback.

- Use the scripts directory as the pyRevit workspace and preserve the full run envelope. Compute the machine plan and standard change-preview from snapshot_json. The display uses generated keys, including for warnings, and disables spreadsheet exports. Show skipped and no-op rows. The apply query consumes both the machine plan and its linked display preview, and checks immutable fields on the fresh inventory. Skip the ownership CLI for zero pre-existing targets. After Keep, use the real created IDs for the ownership hand-off.
- Dry-run verification uses the full runtime record. Its created IDs are provisional. Reread and match the original inventory immediately afterward, before the real run. Verify the real kept result by exact returned IDs/UIDs and compare model geometry rather than view-specific datum extents. Test the existing renderer and the no-op branch. Close only on a native receipt with both operations, independent name/width or elevation checks, exact dry-run additions and post-Keep/post-Discard readbacks. Record source revision, Revit year and engine.

Each relative spacing follows the preceding requested coordinate, even when its name is skipped. Show any existing/requested coordinate difference before approval. Use a native fixture that pre-seeds a level and multi-segment grid, then requests those names with case variation and a different requested coordinate alongside new rows. Verify skipped elements retain their IDs, names and geometry through Keep, Discard and an all-existing repeat. The approved preview precedes the dry run. Recheck the full unchanged baseline, context and policy before sending the same plan to Keep/Discard.
