# Linked MEP penetration proposals and tracking

[Issue #152](https://github.com/zsenarchitect/archi-magic/issues/152) asks for proposed openings with size and clearance where linked MEP crosses host walls or floors. A moved duct must make its opening out of date. [RFC 003](../rfcs/003-mep-support.md#3-phased-implementation-roadmap) describes MEP-PEN-01 as a coordination check for missing sleeves or openings in fire-rated assemblies.

## Read, compute, and track

1. Start with one explicitly reviewed loaded Revit link instance and selected host walls/floors and linked rigid duct or pipe runs. Record the saved project and linked document identities, link instance ID and UID, effective rigid transform, element IDs/UIDs, phase and design option, complete geometry evidence and size fields. Snapshot geometry in host internal feet with a documented coordinate frame. Keep source link and model paths private. Keep the host solid in its native frame. Transform linked points with OfPoint and section axes with OfVector. Compare GetTransform and GetTotalTransform on known points in translated, rotated, true-north/project-north disagreement and mirrored fixtures. Bind the chosen mapping, unit scale and handedness to the read. Use both physical end connector frames and independent outer section measurements. Refuse an inconsistent roll, unknown transform or unsupported reflection. Reject unloaded links, ambiguous document identity and unmeasurable inputs with a per-element reason. Collect no write instructions.
2. Compute deterministic pairs with a swept-envelope broad phase, followed by native solid/centerline intersection and independent entry/exit evidence on opposite principal host faces. Read complete supported host solids, including openings, and transform the entire duct section frame. Cover finite, straight, orthogonal crossings of planar basic walls and planar flat floors first. Propose rectangular openings for supported rectangular ducts and round openings for supported round runs. Supply measured section size plus twice the explicit radial/per-edge clearance and the measured host depth. Verify a positive full interior pass with a bounded line, closed solid, exterior endpoints and trimmed-face clearance. Independently reject face-coincident segments. Use pipe outside diameter and the measured duct exterior envelope, with insulation or lining only when the full installed profile is qualified. Tangent, embedded-end, near-edge, multicrossing, angled, curved, sloped, insulated without a qualified envelope, and unknown profile cases remain explicit review rows. Follow with separate measured projections for oblique and sloped crossings before claiming those as supported. A box overlap or a nonzero segment alone cannot create a proposal. Compare the complete projected opening envelopes in the host frame against each other and all existing manual and tracked cuts. Require a reviewed minimum material web for the host. Incomplete nearby-cut coverage blocks placement on the host. Recheck combined cuts and the retained web after every provisional cut. Include overlapping, just-under-spacing and valid adjacent cases in the native fixtures.
3. Key the first supported crossing by independent saved project and linked-document identities plus link instance, linked run and host UIDs. Reuse the separate identity fields in `skills/am-issue-board/scripts/structural_compare_cli.py:115–124`. Keep source version freshness separate. If replacement or copied-document continuity is ambiguous, report unresolved and require a new reviewed baseline. One exact crossing per pair is required for placement. Keep this identity stable across motion. Separately hash the section, entry/exit pose, host faces, depth, mapping, and clearance. For kept openings, retain paired entry/exit stations in the host frame, approved size, native cut evidence, and the opening UID. Attach one versioned Extensible Storage entity to the created opening in the same reversible model transaction as its cut. Bind schema/version, the opening's own UID, all document/element identities, approved geometry, and cut/pose evidence. Validate fields on every read. A copied tag with mismatching owner, malformed entity, duplicate crossing key, or live opening with lost cut cannot be current. Scan tags and untagged cuts independently of new candidates. Reconstruct a current gross host envelope from the qualified principal planes and outer trimmed loops, ignoring only the independently proven tracked void. Compare this current envelope with the stored host anchors and the current run. An unreadable outer loop or unknown host edit makes the state unresolved. A moved or resized opening with otherwise complete evidence is out of date. A deleted opening leaves no entity and can only reappear as a new candidate requiring a new approval. Never infer a historical opening from a current candidate. Prove Keep, Discard, Undo, a tracking-write failure after cut, and save/reopen. [Autodesk Extensible Storage](https://help.autodesk.com/cloudhelp/2024/DEU/Revit-API/files/Revit_API_Developers_Guide/Advanced_Topics/Storing_Data_in_the_Revit_model/Revit_API_Revit_API_Developers_Guide_Advanced_Topics_Storing_Data_in_the_Revit_model_Extensible_Storage_html.html) Emit current, out of date, unresolved, duplicate, or untracked. A moved run that leaves the original host entirely is out of date only after a complete scan of the relevant linked run and host; an unavailable link or host is unresolved. Never silently relink, resize, or recreate a tracked opening. Keep face/cut and tracked-identity checks separate from geometric tolerance.
4. Bound the first read to 100 hosts and 100 runs, 10,000 broad-phase pairs, 1,000 actual solid–curve calls, depth 8, 100,000 accounted geometry visits, 10 seconds and 2 MiB or the smaller verified bridge limit. Check monotonic time and work before every traversal unit and native call and after native calls. A single blocking native call can exceed the cooperative budget. In that case return incomplete on recovery and qualify process isolation and bridge timeout before production use. Include existing cuts and tracking reads in the accounting. Report caps and exact unread scope. Truncated, capped, or partial reports can never enable a write or declare records out of date. Limit the first reversible placement batch to 10 cuts, with the same geometry ceilings and a separately measured 30-second provisional deadline, excluding human approval. Prove one below-cap successful case, one cap-plus-one refusal, and consumer rejection of incomplete and truncated receipts. `skills/am-issue-board/scripts/read_structural_geometry.py:33–45,123–135` supplies the bounded-reader pattern. Independent offline tests use prepared measurements; they do not prove native crossings.

## Guarded placement and qualification

5. Use an explicit symbol map by host and section shape. Reacquire the native trimmed face reference from HostObjectUtils immediately before each placement, after earlier regeneration or cuts. Use interior/exterior faces for walls and top/bottom for floors. Require a reference direction tangent to the face and the correct signed cut axis. Reject references derived from copied geometry. [Autodesk HostObjectUtils](https://help.autodesk.com/cloudhelp/2025/CHS/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Geometry/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Geometry_Geometry_Utility_Classes_html.html) Verify exact symbol identity, placement mode, approved typed size/clearance fields and writable scope in the disposable host. For a qualified unattached void use CanBeCutWithVoid, IsVoidInstanceCuttingElement and AddInstanceVoidCut. Prove the exact host-to-opening relationship with InstanceVoidCutExists and independently measure material removed through the full depth and inside the allowed profile. Hosting alone is insufficient. [Autodesk InstanceVoidCutUtils](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/68b4818a-d737-be1e-0347-ebe305fe3b70.htm) Unknown families, existing manual opening conflicts, unproven cut, changes to shared or type-level parameters, and unsupported reference frames block placement. Treat fire-rating text as context only. Require separate human review for life-safety approval. Include exact affected host IDs in ownership scope and hash the approved annotated preview with its source/host/mapping and writable-instance-field basis. Require the user to approve that preview before the first dry run. Recheck ownership, source, target, mapping and effective ask policy at dry run and replay. Disable real writes until the installed bridge's ask-policy binding is proved. Permit only measured opening additions and explicitly allowed host effects. Verify every new instance and actual host cut while reversible. Roll back the full batch on any mismatch. Check independent rollback readback before replay. Compare full effect IDs and measured cut state against the dry run. Keep creates one named undo entry. Require saved distinct trial, bridge decision with approval:user, and fresh query records. Fresh post-Keep readback must reconcile tracking and yield no duplicate proposals. On a Keep mismatch stop and identify the named Undo entry.
6. Use a saved disposable Revit 2026 project and a known linked model on the supported CPython bridge. Independently author reference walls, floors and linked runs with known dimensions. Compare predicted and measured entry/exit points and cut envelopes within a reviewed fixture tolerance. Verify different wall/floor runs, both section shapes, translated/rotated link, supported mirror handling or explicit refusal, native Keep and Discard, and a second target failing late without retaining the first. Move a duct within its host and then away from the original host and verify both are out of date. Leave a second untouched run current with an actual existing void. Check unloaded link, same link model twice, duplicate tracking, tangent, near-edge, partial/capped scan, stale mapping, unsupported shape, and zero-write rerun. Save sanitized evidence from the exact candidate revision. A runnable preview alone leaves #152 open.

7. Hand off a report-only MEP-PEN-01 result with host and linked element identities, system names, and host-frame XYZ to the existing issue-board review. Use a stable crossing key to avoid duplicate findings. Include fire-rating context where readable. Keep raw paths and linked references private. Board edits use the board's separate safe-change approval. This is the #152 input to the #186 integration, not proof that #186 is complete. See `docs/rfcs/003-mep-support.md:22–27` and `docs/plans/2026-11-09-backlog-delivery.md:18`.

## Rollout and dependencies

- Deliver pure proposal and tracking logic, then native linked and host evidence, then guarded placement, then native acceptance and merge of the write path. Verified read-only stages may merge independently after CI while #152 remains open. Each phase adds testable behavior and depends on its predecessor. Disable the recipe or revert its merge to roll back code. Use a disposable model and Discard or the verified named Undo entry for native rollback. Never delete a prior opening as part of this rollout.
- External dependencies are the supported Windows Revit host, a qualified installed bridge, sanitized fixtures, and exact local cutting families for each supported profile and host. Verify these through native reads before enabling placement. The Windows host was offline when this plan was drafted.
- Open questions for fixture verification are the correct instance/symbol geometry transform under reflection, trustworthy opposite-face references for each host category, and whether candidate cutting families expose observable cut evidence. If any cannot be demonstrated, surface the specific capability as unresolved. Preserve the wider issue scope until the native controls pass.
- No automatic repair, cross-model writes, fitting transitions, fire-stopping certification, or support inferred from vendor category names. Keep each unqualified case visible in the report.
