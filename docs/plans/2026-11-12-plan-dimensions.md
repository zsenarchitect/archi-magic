# Reviewed plan dimensions for grids, walls, and openings (#146)

[Issue #146](https://github.com/zsenarchitect/archi-magic/issues/146) requests overall and grid dimension strings in plan views, opening dimensions on chosen walls, and a report of unresolved references. Baseline `0c523067c4313bd9e8c3898be4ffd32d874463d7`. The existing [safe-change workflow](../../skills/am-safe-change/SKILL.md) covers ownership, dry run, Keep/Discard, and readback. The [Revit API notes](../../skills/am-revit-api-docs/SKILL.md) identify the dimension type overload but there is no dimension recipe in the baseline.

## Read and preview

1. Use a saved host project, an active floor plan, one reviewed linear dimension type, and explicit host IDs. Bind the project UID and path digest, view and dimension type IDs and UIDs, view frame and relevant crop state, and all selected source identities. Reject templates, perspective, dependent views until independently qualified, linked sources, ambiguous identities, and incomplete visibility evidence. Capture native per-row diagnostics. Confirm the exact version and context before relying on each API.
2. For grids, review one string per set of straight parallel host grids. Read the straight `DatumExtentType.ViewSpecific` or model extents used in the view and require the operator's reviewed placement line to intersect every supported grid in that view. Test a datum element reference in a disposable native fixture. Read the stable references and grid crossings, sort by projected distance along the reviewed dimension axis, and reject duplicates, coincident stations, sloping or nonparallel lines, missing geometry, or a line outside the reviewed view. Keep the source of the datum reference explicit. [Autodesk grid extents in a view](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/2f93dd88-baac-8e61-377e-b937f3faaff6.htm)
3. For overall dimensions, read the reviewed interior or exterior side of two straight parallel host walls. Resolve native planar side-face references, verify face ownership and opposing parallel planes in the view frame, and project their intersections onto the dimension axis. For stepped, split, or stacked walls with ambiguous faces, show the candidates and stop. Require explicit selection of the exact intended reference when more than one face can supply a valid span. A location line or bounding box alone cannot supply the reference. [Autodesk wall side references](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/589b9363-c2cc-52d9-6ba1-fc8e8f912b27.htm)
4. For openings on the chosen walls, read actual hosted door and window instances in the plan. Require one qualified left reference and one right reference per opening from the family instance. Bind the wall, instance, type, position and flip state. Use exact reference positions when Revit exposes them. Otherwise qualify the family reference convention on a disposable fixture using independent measurements, and block a row whose reference distance cannot be established. A nominal type width can be shown as supporting information. Missing references, hidden or unsupported openings, and reversed or ambiguous reference pairs remain visible as blocked rows. [Autodesk family instance references](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/a8a7dc74-db8e-a7b6-a9c8-869397cca6b4.htm)
5. Compute a deterministic preview with the exact line, ordered stable references, expected segment lengths in Revit internal feet, and the native dimension type. Bind the saved view frame, source identities, and dimension line into a versioned apply payload distinct from other safe-change plans. Report proposed, blocked and already-existing strings separately. An existing dimension with the same ordered references in either direction, matching type, and the same line within the placement tolerance is a no-op. Reuse the dimension preview renderer. Start with up to 20 strings and 64 references per string, bounded inventory and output, and a verified placement tolerance. A blocked row cannot enter a write set. A new preview may explicitly select only resolved rows while preserving the diagnostics in the original result. [Autodesk stable reference representation](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/9d821d63-5b4a-b814-25b2-b92f7d5d1425.htm)

## Native qualification and execution

6. Use a disposable project and ask policy before the first write. Check the project, context and ownership, show the preview and obtain approval for the exact trial. Under `dry_run: true`, use a rollback probe to determine which native grid, wall and opening references the selected plan and dimension type accept. Re-read the full basis immediately before any transaction. Reparse stable references and verify the same owner, reference kind and geometry before constructing the native `ReferenceArray`. Start one transaction for the approved batch. Use the overload that accepts the dimension type element. If any reference or line fails, roll back the batch. Report the affected request and source IDs. [Autodesk NewDimension overload](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/475aab91-19d3-5884-d3eb-18dfc0d4004f.htm)
7. Before provisional commit, regenerate and read exact dimension IDs and UIDs, owning view, type, line, ordered reference identities and segment values. Read a two-reference dimension and a multi-segment string through their distinct native properties. Compare native values to independently grounded expectations, within 0.001 ft initially. Record if reference or segment order is reversed and only accept reversal when reference/value pairs remain consistent. Reuse the transaction and exact-effect patterns in `skills/am-safe-change/scripts/focus_view.py:170–222` and `skills/am-safe-change/scripts/focus_view_preview.py:156–174`. Capture full provisional events and require exactly the reviewed dimension additions, zero unexpected changes, and no edits to source elements or other documents. If the runtime cannot prove this while rollback is available, keep the workflow at qualification. Verify a fresh unchanged baseline after a rollback or Discard. [Autodesk dimension members](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/210f88be-e3c5-26a4-7dd8-3296f6725cce.htm)
8. Before Keep, reread context, policy, ownership, view, references and expected effect scope. Use the same reviewed payload and rerun checks before allowing persistence. Read the actual kept dimensions independently. Repeating the original request should yield no new dimensions. Restore from the disposable fixture baseline if Keep or Discard cannot be verified, and retain the full run records.

## Acceptance and open questions

Use a saved Revit 2026 fixture with unequal grid bays, rotated but parallel grids, two selected wall faces, a door and window with differing widths, a mirrored instance, and one missing or ambiguous reference. Verify dimension values against independent model measurements and list each blocked reference by source and reason. Test wrong type, shifted geometry, stale view, duplicate strings, incomplete telemetry, and a late failure after an earlier dimension was created. Prove full baseline restoration after rollback and Discard. Record the Revit build, revision, fixture, and exact before, trial and kept reads.

The authorized Windows Revit test host and a representative fixture are external dependencies. The main unknowns are the accepted native reference form for grids, the stable projection of each supported family reference, and the visibility of complete effects before Keep. Revit API names establish possible methods. The fixture must qualify their combination. Curved or linked geometry, automatic dimension style changes, and deleting existing dimensions are outside the initial acceptance contract.
