# Reconcile door and window elevation legends (#147)

Baseline `d3ace4f3b89bf0feef535812631911abba056b08`. The [existing inventory](../../skills/am-reference-samples/scripts/read_opening_types.py) reads placed host types, marks, sizes and legend elevations. The gap is confirmed. It does not add, label or reconcile components. Issue #147 asks for one labeled elevation per placed type and an update when that set changes.

## Native prerequisites

- Follow the [Revit 2026 legend component recipe](../../skills/am-revit-api-docs/SKILL.md). Have the operator place one front-elevation seed in a separate source legend. Select a dedicated target legend and text note type. Record both legend IDs and UIDs, source seed ID and UID, its type and direction, and the selected text type ID and UID. Read the source only.
- Qualify [CopyElements](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/0f6a7a2e-13b9-008a-4c41-951a0702d16b.htm) for that pair of legends. Check [the view-to-view transform](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/d28d5afd-6784-90be-4f6b-7bc35b997e3a.htm) and destination-plane translation. Copy only the reviewed seed and test retyping to both a door and a window. Confirm native bounds, front direction and successful inner commit in the guarded runtime dry run. Verify rendering after Keep on the disposable fixture. [Autodesk's developer blog](https://blog.autodesk.io/extentelem-and-square-face-dimensioning-references/) reports a successful cross-legend copy when the non-graphic extent element is excluded. If that route fails, stop. Any alternative seed route needs a separate review and proof that it can clear the last row and restart from zero.
- Use [TextNote.Create](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/b5e7dc0d-3b46-6747-dfe0-83c93b2057a2d.htm) with the verified view and type. Confirm the written label and its final bounds. A valid native bounding box does not establish visibility.

## Read, compute, write and verify

1. Extend the existing bounded reader to collect the host placed-type census, both views, the exact seed and text type, every target view-owned graphic and all viewports that display the target. Read IDs as decimal strings and use type UIDs as row keys. Report current front elevations separately from the existing front-or-back summary. Exclude linked documents. Show duplicate and missing marks. Use type dimensions when instance data agrees. When a type dimension is absent, use an observed instance dimension only if every placement agrees and contributes a value. Require a reviewed label for missing or variable data.
2. Bootstrap an empty dedicated target. On refresh, identify verified managed pairs before classifying manual objects. Use a local receipt from a committed Keep or approved auto run and a distinct independent query. Bind it to the project, legend, both run IDs, type UID, exact component and text IDs and UIDs, owner view and element kind. Require unique pairs and compare author-editable state, including type, direction, position, note text, type and supported formatting. Treat an unreadable or changed author-editable field as unresolved. Recompute type-derived geometry bounds from the fresh census. Preserve manual graphics. Block unproven duplicates, unplaced elevations, orphaned pairs, unknown directions and bounds in the affected region. A missing or mismatched receipt cannot authorize a refresh or retirement.
3. Compute add, refresh, retire and unchanged rows. Retire only verified managed pairs for types absent from the placed census. Show their exact IDs in the preview. Bound one run to 100 managed rows, 1,000 target- and sheet-owned graphics combined, 20 sheet viewports, and a ten-second soft read budget checked between API calls. Stop on incomplete coverage. Use a reviewed grid in the target view with at least 1/8 in of paper-space clearance and cells bounded by the available viewport space. Allow at most 50 ft of model-space width or height per component. Use the target scale to convert paper spacing. Measure actual component and note bounds after regeneration. Check the available rectangle on every sheet displaying the legend. Use both viewport and label outlines. Include adjacent viewports and other sheet graphics. Stop on unknown bounds or overlap. Keep unplaced views within their reviewed grid and report that no sheet fit was tested. Refuse the complete batch if any row cannot fit.
4. Use [am-safe-change](../../skills/am-safe-change/SKILL.md) preview, ownership and side-effect checks. Include the target and every modified or deleted element in the ownership check. Recheck active document and policy and compare a fresh complete basis before one transaction. Refuse pinned or grouped edit/delete targets. Check each target's ID, UID, owner view, kind and dependencies. Restrict copy results to the one expected component in the target. For retirement require [Delete](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/f4ce9113-b164-954e-5025-7b4edbdcc07d.htm) to return exactly the approved pair IDs. Roll back on an extra dependent ID or unexpected state. Compare the entire target, source seed and affected viewport state before committing. Require both [Commit and GetStatus](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/32714010-7138-f64f-8fde-a310354448e3.htm) to establish a committed inner transaction. Read back again before returning. Raise a failure if the post-commit read differs so the runtime can roll back the outer group. Treat Pending or inconsistent status as unresolved. Stop further writes and withhold a receipt.
5. Recover the full runtime record with get_run. Check exact added component and note IDs from the returned pairs, modified IDs from reviewed managed pairs, and deleted IDs from approved retirements. Reuse the existing ownership and side-effect helpers and the focus-view full-ID telemetry pattern. Refuse unknown IDs or other-document changes. Treat any target viewport telemetry separately and require matching observed geometry and prior approval. Check that the runtime reports an outer dry-run rollback and independently read the original baseline before the real run. Recheck policy and ownership. Under auto get the second approval after the dry run. After Discard, verify the original state. After Keep or an approved auto commit, use a separate read to compare type, direction, label text, layout, source seed, manual elements and viewport state. Record a replacement receipt only after that read matches. Use Undo if a kept result differs.
6. Test initial generation, a no-op, a mark and size update, a new placed type, retirement of the last instance, missing receipt, duplicate or manual rows, a pinned or grouped pair, layout overflow, unexpected deletion, native commit failure, and rollback. Use a disposable Revit 2026 project with at least two placed door types and two placed window types, a duplicate placement, a loaded unused type, and an unrelated note. Independently compare the full placed type UID set to the rendered front-elevation type UID set. Check exactly one correctly labeled elevation per placed type, on and off a sheet. Exercise two placements with one that overflows and verify refusal of the whole update. Exercise dry run, Discard, Keep, update, zero rows, restart after zero, and a clean rerun. Record Revit build, engine, source revision and measured results. Keep #147 open pending native verification and merge.

## Scope and dependencies

Use a dedicated host legend. Preserve unrelated manual graphics, family definitions, marks, placements and linked models. The operator supplies a usable seed in a separate legend. A disposable Windows Revit 2026 host is needed for native copy, layout, commit and readback evidence.
